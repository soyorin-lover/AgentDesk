本方案从产品用途、信息结构和使用流程重新设计 AgentDesk，供用户讨论与 Claude 后续设计使用。它不是前端实施指令，也不表示其中的建议已经获得确认。现有原型仅供流程问题参考。

## 1. 要做出的产品

AgentDesk 是独立开发者长期使用的个人开发工作台。用户在这里围绕项目组织工作，把任务交给不同 Coding Agent，跟进执行，处理必要决策，检查代码与测试结果，最终完成交付。

长期至少管理 Codex、Claude Code、DeepSeek Harness，并能容纳更多引擎。用户应当通过项目和任务理解自己的工作，通过智能体管理选择执行工具。

产品以本机 Web 应用起步，面向 Windows 和 Linux 的桌面使用。应用感来自稳定的导航、连续的工作上下文、清晰的操作反馈与可靠的状态保存；是否采用独立桌面外壳，留给后续工程决策。

设计成功的表现：打开应用能找到要继续的工作；进入任务后能专注推进；需要审查时能充分阅读代码；多个智能体工作时仍能理解各自负责什么；离开并返回后能接续此前的操作。

## 2. 已确认要求与本稿假设

### 已确认

- 浅色、安静、精致、现代简洁，适合长时间使用。
- 功能分模块进入，逐层展开，初始界面避免大量信息。
- 参考 Codex、Claude、DeepSeek Harness 所代表的现代工作软件气质；具体布局重新设计。
- 面向多种 Coding Agent，不能把整套产品定义成 Codex 专用界面。
- Claude 负责前端设计与实现，Codex 负责产品协调、接入、后端和工程集成。
- 分批开发；已完成的第一批只证明 Codex 最小接入能力。

### 本稿建议，仍可调整

- 采用项目中心的应用结构，任务是主要工作单元。
- 一级导航只保留项目、收件箱、智能体；设置位于侧栏底部。
- 首次打开进入项目入口；日常重新打开恢复上次位置，并提供明确的“项目”入口。此前讨论的“回到上次任务”和“项目作为入口”在这里作为不同使用情景处理，尚待确认。
- 主设计尺寸按 1440 × 900 CSS 像素，兼顾 1280 × 800 与更大桌面窗口；这些是设计基准，不是用户设备的已知参数。
- 中文为主要界面语言，键盘与鼠标为主要输入，常规桌面观看距离。
- 初期以手动分派任务为设计基线；同任务多智能体交接与自动编排尚未确定。

## 3. 整体设计取向

可选结构包括会话中心、全局监控中心、项目中心。会话中心便于即时交流，但项目目标、代码审查和交付容易散落；全局监控中心便于巡视大量运行，却会增加初始信息量。

本稿推荐项目中心：以项目组织任务，以任务承载交流与执行，以独立审查界面承载代码决策。全局只保留跨项目的必要入口。它适合用户持续推进自己的软件项目，也能自然容纳多个执行引擎。

核心原则是：每个界面围绕一个当前目的组织内容。模块之间通过导航连接，辅助信息通过明确入口展开。

## 4. 信息架构

```text
AgentDesk
├─ 项目
│  ├─ 项目入口：最近项目、打开本地项目
│  └─ 当前项目
│     ├─ 概览：继续工作、当前重点、需要关注的事项
│     ├─ 任务：整理与选择任务
│     │  └─ 任务工作区
│     │     ├─ 执行：与智能体交流、查看当前工作
│     │     ├─ 变更：审查文件、检查结果、提出修改
│     │     └─ 详情：目标、验收条件、运行历史
│     ├─ 交付：接受结果、集成与最终验收记录
│     └─ 项目设置：仓库、分支与项目偏好
├─ 收件箱：跨项目需要用户处理的事项
├─ 智能体：配置与管理不同执行引擎的实例
└─ 设置：应用偏好、连接与诊断
```

“执行”“变更”“详情”是同一任务下的局部视图，不占据一级导航。项目内的交付负责项目层面的整合记录，任务内的变更负责具体代码审查。

收件箱收集已有任务中的请求，不再建立一套独立任务状态。点击事项进入对应任务和具体请求；处理后返回收件箱仍保留筛选与位置。

## 5. 应用外框与导航

### 稳定外框

左侧使用可收起的轻量导航栏，建议宽度 224–240 px。顶部是产品标识与项目切换器，主体是少量全局入口和当前项目入口，底部放设置与本机服务状态。

主区域顶部使用约 52–60 px 的上下文栏，说明当前位置，并放当前页面必要操作。面包屑示例：项目 / AgentDesk / 登录异常修复。标题只在一个主要位置出现。

每次只突出一个导航位置。进入任务后，侧栏仍保留返回项目任务列表的入口；需要切换其他任务时使用任务切换器或列表，不额外常驻完整任务栏。

### 连续使用

- 保存最近项目、任务局部视图、筛选条件和阅读位置。
- 切换任务保留各自未发送的输入；刷新后能恢复本机草稿。
- 长时间执行在用户切换页面后继续，侧栏用简短状态和数量提示。
- 浏览器返回/前进、直接打开任务地址与页面刷新应保持可理解的位置。
- 连接中断时保留现有内容和输入，用局部提示说明状态可能过时。

### 页面、抽屉与弹窗的分工

长时间阅读、代码审查和智能体配置使用页面。任务背景、一次运行的详情、次要配置使用可关闭的抽屉。短小且需要明确完成的动作使用对话框，例如确认集成。

只允许一个主要辅助抽屉展开；从抽屉深入复杂内容时转到页面。弹窗关闭后焦点回到触发位置，未完成的长文本编辑保留草稿。

## 6. 各模块设计

### 6.1 项目入口

目的：选择工作环境，继续最近工作。

默认显示最近使用的项目列表和“打开本地项目”。每项只显示名称、简短描述或仓库标识、最近活动时间；有待处理事项时增加小型数量提示。项目多时提供搜索、固定与归档筛选。

首次使用采用简短空状态：说明选择本地 Git 仓库即可开始。环境检查在选择之后按步骤呈现，避免首屏出现长篇安装说明。

### 6.2 项目概览

目的：建立当前项目的工作方向，并快速进入下一步。

首屏优先展示项目名称与一句当前目标、“继续工作”入口、少量当前任务和需要用户处理的事项。任务多时展示有上限的摘要和“查看全部”，不延长首页。

运行数量、最近交付等可用简短文字表达。没有可靠数据时不展示完成百分比；不以装饰性图表填满页面。仓库路径、分支、环境检测和历史活动放入项目详情。

### 6.3 任务模块

目的：把想做的工作整理成可执行、可审查的单元。

默认使用清晰的任务列表，按进行中、待处理、待审查等有意义的条件筛选。每行显示标题、主要状态、负责人或执行智能体、最近活动；完整描述进入任务后阅读。看板是后续可选视图，不作为首轮必须实现的功能。

新建任务使用独立的轻量编辑页：先填写目标，再选择智能体。验收条件和必要参考资料在同页的后续区域填写；高级运行配置通过展开入口进入。允许先保存草稿，执行前提示缺失的必要条件。

选择智能体时区分引擎与已配置实例，例如“Codex · 工程实例”。模型和权限配置放在次级设置中。若只有一个可用实例，可预选但允许修改；未接入引擎不能作为可执行选项。

### 6.4 任务工作区：执行

目的：理解当前工作、提出指令、处理任务内决策。

顶部紧凑显示任务标题、当前智能体身份与主要状态，提供任务局部导航。中心是可阅读的会话与执行记录，底部是输入区。正文保持舒适阅读宽度，辅助面板关闭时也不让文字横贯整个大屏。

智能体自然语言输出正常展开。连续工具调用按一次工作过程归组，例如“检查了 4 个文件，运行了 2 项检查”，可以展开查看真实内容；失败、用户问题与审批请求保持可见。收起规则不能遮蔽待处理风险或执行失败。

输入区根据执行阶段明确标示“发送”“补充指令”或其他真实支持的动作。中止位于易找到的执行控制区，与发送分开。请求发送后显示等待确认；未收到服务端确认时不能表现为已经生效。

任务问题就地展示，用户可回答或查看背景。审批请求显示动作、目标、影响与允许/拒绝选项，详细命令可展开，但影响范围不能折叠隐藏。请求过期或已在其他位置处理后，显示结果并移除可执行按钮。

用户向上阅读时不强制滚回底部；新内容以“有新消息”入口提示。切换任务时保存阅读位置。任务目标、验收条件和运行历史通过详情视图或抽屉查看。

### 6.5 任务工作区：变更与检查

目的：让用户充分审查产出并作出决定。

进入变更视图后，代码获得主要空间。左侧为可折叠文件列表，中心为 diff，检查结果通过局部切换或可展开区域查看。全局侧栏可收起；会话和跨任务待处理列表不常驻占用代码宽度。

提供统一与并排 diff 视图、文件搜索、下一个变更位置。宽度不足时默认统一视图。长行允许在代码区域横向滚动，页面本身不产生无意义的横向滚动。

检查结果显示执行命令、运行时间、退出结果和可查看输出；清楚区分通过、失败、未运行和结果过时。代码再次改变后，旧检查仍可查阅，同时标明对应旧版本，不能继续呈现为当前有效结论。

主操作随阶段变化：审查时可以“要求修改”或“接受结果”。接受记录对应本次变更版本；后续变更使此前接受失效并重新待审查。提出修改时保留文件与位置上下文，回到执行视图继续交流。

### 6.6 项目交付

目的：把已接受的任务结果组织为实际项目交付。

列表展示可集成任务与历史交付。进入一项后展示来源任务、变更范围、检查证据、目标分支和集成状态。确认操作应明确说明将修改哪个本地分支。

集成成功后显示真实提交或分支结果，并引导做最终验收；冲突时保留现场，列出冲突文件与可行处理路径。执行完成、用户接受、集成成功、最终验收分别表达，不能用同一个绿色“完成”覆盖。

首个可用版本只需完成单任务交付闭环。批量集成、依赖排序和自动解决冲突属于后续能力。

### 6.7 收件箱

目的：集中找到需要用户作决定的事项，减少巡视多个任务的负担。

按待回答、待审批、待审查筛选。每项只显示项目与任务、请求摘要、等待时间，点击进入具体处理位置；列表默认不展开所有请求全文。

计数仅包含需要用户动作的事项。普通运行事件进入任务历史，避免收件箱成为日志流。事项处理后更新计数；过期事项解释原因，不能继续点击确认。

### 6.8 智能体管理

目的：连接和配置执行工具，了解它们当前是否可用。

列表以配置实例为单位，显示名称、所属引擎、连接状态和简短可用性。进入实例详情后设置执行程序或连接方式、模型与默认偏好，并查看能力验证情况。

已连接、可执行、执行失败与额度受限分别说明。引擎已安装或握手成功不能显示为完整可用。未接入的引擎放在明确的规划区域，避免与真实可选实例混淆。

多引擎使用共同导航和任务语言，身份以名称与小图标区分；不使用三套大面积品牌配色。能力不同的操作根据实际情况显示，并在必要位置解释原因。

## 7. 信息分层规则

| 层级 | 用户能看到什么 | 典型内容 |
| --- | --- | --- |
| 默认层 | 当前对象、主要状态、下一步 | 任务标题、正在等待回答、查看变更 |
| 工作层 | 完成当前操作所需内容 | 会话、问题、审批范围、文件 diff |
| 详情层 | 用户主动查看的背景与证据 | 验收条件、运行历史、完整检查输出 |
| 诊断层 | 排查问题所需技术信息 | 请求标识、连接诊断、适配器错误 |

“渐进展开”不能成为隐藏重要事实的理由。失败、权限影响、未运行检查和未保存输入在相关操作位置可见。技术标识不作为普通用户的主要标题。

同一状态在当前页面只保留一个主要展示位置。全局收件箱计数负责提醒，任务内的请求负责解释，两者不会同时展示重复的完整卡片。

## 8. 核心使用流程

### 从想法到执行

打开项目 → 创建任务草稿 → 写目标与验收条件 → 选择可用智能体 → 确认执行范围 → 开始执行 → 留在任务或返回项目。

### 执行中需要用户

出现收件箱数量提示 → 进入请求所属任务 → 查看问题或审批影响 → 回答/允许/拒绝 → 等待真实状态更新 → 继续当前工作。

### 从产出到交付

执行结束 → 任务待审查 → 查看 diff 与检查 → 要求修改或接受结果 → 项目交付中集成 → 查看结果 → 最终验收。

### 离开与返回

切换页面或关闭窗口 → 后台执行继续 → 再次打开恢复工作位置 → 更新最新状态 → 保留原有草稿与阅读位置。

### 多智能体并行

在不同任务中分别选择智能体 → 项目任务列表显示各自负责人和状态 → 收件箱集中提示需要处理的事项 → 进入其中一个任务专注工作。

同任务跨引擎交接不在本稿中假定已实现。未来若引入，需要设计明确的交接材料、责任变化与历史保留方式，再补充流程。

## 9. 视觉语言

整体气质：温和的浅色背景，干净的工作表面，清晰的文字秩序，少量蓝色交互强调。精致感来自对齐、间距、排版和状态反馈。

以下数值是首轮视觉样稿的起点，需在实际画面中校正，不是已验收的设计资产。

| 语义角色 | 建议起点 | 使用方式 |
| --- | --- | --- |
| 应用背景 | #F6F7F9 | 大面积安静底色 |
| 主表面 | #FFFFFF | 当前工作区域 |
| 辅助表面 | #F0F2F5 | 分组、代码背景或选区 |
| 主要文字 | #242833 | 标题与正文 |
| 次要文字 | #626A78 | 辅助说明，仍需可读 |
| 分隔线 | #E1E5EB | 轻量结构分隔 |
| 交互强调 | #365FCA | 主操作、链接、焦点 |

正文从 16 px 起，基于 1.2 比例建立约 13/16/19/23 px 的有限字号体系，使用 rem。小字号用于次要元信息，代码字号提供缩放。正文行高约 1.5，中文段落控制阅读宽度。优先系统字体，代码使用系统等宽字体。

间距以 4/8/12/16/24/32 px 为基础。控件圆角约 6–8 px，浮层约 10–12 px；同类组件统一。使用少量细分隔线，平级内容优先通过留白分组。阴影集中用于菜单、抽屉和对话框等浮层。

普通运行使用中性状态，成功提示克制，警告与错误只在相应事实出现时强调。状态同时具备文字或图标。选中状态与悬停状态可辨，图标风格与线宽统一。

浅色是本轮交付主题。颜色使用语义 token，为后续主题留出结构；本批不扩展暗色样稿。

## 10. 操作、尺寸与反馈

- 常用操作有文字，图标按钮有可访问名称；关键含义不依赖悬停才能发现。
- 桌面常用控件高度建议 36–40 px，小图标也保留足够点击区域；触控适配时放大交互目标。
- 所有交互可通过键盘完成，焦点清晰，Tab 顺序合理，Escape 关闭临时浮层。
- 全局搜索可搜索项目与任务。命令面板是后续效率增强，不作为首轮必需功能。
- 输入默认 Enter 发送、Shift+Enter 换行，提供偏好选项，并正确处理中文输入法组合输入。
- 动效约 120–220 ms，用于展开、切换与反馈；尊重减少动态效果偏好，不持续装饰性闪动。
- 1280 px 及以上保持主要工作布局；窗口缩小时先收起全局侧栏与辅助详情，代码切换统一 diff；更窄窗口转为单主区，保留导航与返回入口。
- 字体放大与浏览器缩放后，操作不被遮挡。主正文、交互文字和焦点需验证对比度，不能通过过浅文字营造安静感。

## 11. 异常与边界状态

| 情景 | 界面行为 |
| --- | --- |
| 正在加载 | 只在相关区域显示骨架或进度，保留应用外框 |
| 引擎不可用 | 在启动位置说明原因，保留草稿并提供配置入口 |
| 网络或上游失败 | 显示失败阶段与恢复选项，保留已有输出与变更 |
| 模型或额度不可用 | 明确当前实例无法执行；不自动更换模型继续 |
| 连接中断 | 保留内容，标示状态未更新；重连后核对实际状态 |
| 中止执行 | 显示等待确认，收到终态后标示已中止，并保留现有变更 |
| 恢复会话 | 明确恢复上下文；不承诺恢复已结束的系统进程 |
| 检查未运行 | 明确写“未运行”，接受操作处可看到该事实 |
| 集成冲突 | 保留工作区与冲突信息，提供处理入口 |
| 原型数据 | 在应用外框用简短常驻标识标明演示，关键结果注明模拟 |

长时间执行展示已知阶段、经过时间与最新活动。没有可靠进度数据时不虚构百分比或剩余时间。通知使用局部提示和数量标记；只有当前必须作决定的操作才中断工作。

## 13. Claude 下一轮设计交付要求

## 14. 评审标准

- 第一眼能识别当前位置和下一步，不需要阅读多块重复状态。
- 项目、任务、执行、审查和智能体管理各有清晰入口与目的。
- 进入审查后代码是视觉主体；进入执行后当前任务是视觉主体。
- 多引擎身份清楚，未接入能力与模拟结果没有冒充真实运行。
- 导航返回后草稿、筛选和位置保持；长时间执行不强迫用户停留。
- 失败与影响范围清楚可见，正常工作时没有持续警报色和说明横幅。
- 字体、缩放、焦点、长内容、窗口变化不会破坏核心操作。
