## 2026-10-08 Codex 接入能力更新

第一批已有 CLI 验证器，还没有 HTTP 后端或可供前端调用的稳定接口。详细证据见 CODEX-BATCH-01-RESULTS.md。

- Windows / Codex 0.154.0：HTTP 对照模式已验证真实文本事件、指定文件修改及 Git diff、多轮上下文、进程重启后的同一会话恢复。
- gpt-5.6-luna 已验证执行中补充被接受、中止收到 interrupted；不承诺补充指令一定完整执行。中止不回滚文件。
- 两个独立示例 Git 仓库的并行会话已通过，事件重叠且差异各自隔离；这不等于产品 worktree 调度器已实现。
- 文件审批接受/拒绝已有真实证据：拒绝不改文件，接受只改指定文件；支持关联 threadId / turnId / itemId 与等待 serverRequest/resolved。命令升级审批仍未实测。当前仍无 Web 后端，原型审批操作继续标示模拟。
- 默认上游传输出现错误/超时；服务器模型列表不保证账户当前可执行。需要保留网络/上游失败、模型不可用、usageLimitExceeded 和待恢复等状态。
- 恢复的是会话上下文，不承诺恢复外部系统进程。Linux 尚未实测。执行完成仍需用户审查、接受、集成和验收。

## 第 2 批 A 后端能力更新（2026-10-08）

现已有本机 API，使用说明见 [BACKEND-USAGE.md](BACKEND-USAGE.md)，新证据见 [CODEX-BATCH-02-RESULTS.md](CODEX-BATCH-02-RESULTS.md)。当前是一处专用仓库、一项任务、单运行的后端，支持保存任务、执行、事件分页/SSE、请求中止、快照审查、反馈续接和人工接受。两轮真实修改/接受及中止有新 Windows 证据，前端尚未联调，不将整个原型标为真实可用。

任务与运行分开；202 只表示动作记录成功；checks 始终 not_run。读取 Task 返回 task/run/snapshot/lastEventSeq/availableActions，写操作携带 expectedVersion 与 Idempotency-Key。接受绑定当前快照，不提交或集成。外部文件变化需显式刷新快照，页面不能暗示有实时文件监听。

审批、提问、运行中补充、自动恢复和其他引擎尚无业务 API；自动 worktree、检查执行与代码集成也未实现。界面按 availableActions 和能力边界处理，不因第一批协议证据展示本批不存在的操作。视觉重设计的优先级和评审流程不变，本更新不要求重写原型或立即开展前端联调。

方案讨论完成后，下一轮优先交付项目概览、任务执行、变更审查、智能体管理四组关键画面及较小窗口布局。完整要求见 DESIGN.md 第 13、14 节。此时仍处于设计阶段，未授权全量前端重写。
