# AgentDesk 前端开发任务书

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans，按任务完成与验证；只有独立子任务才考虑 superpowers:subagent-driven-development。

**Goal:** 把已确认的项目首页、流程图、任务会话体验落到正式 React 前端，逐批接真实契约。

**Architecture:** 保留现有 ApiClient、真实会话层和能力门禁。以 projectId/taskId 组织路由与状态；设计稿只作为视觉和流程参考，不把整份 HTML 搬入 React 或作为生产数据源。

**Tech Stack:** 既有 React 19 / TypeScript / Vite / CSS；不默认新增 UI/图/状态依赖。

**Spec:** [总路线](2026-10-09-development-roadmap.md)、[最新产品决定](../../PRODUCT-DECISIONS-2026-10-09.md)、[DESIGN](../../../DESIGN.md)、[B05](../../BACKEND-BATCH-05-API.md)。

## 2. Global Constraints

沿用总路线全部约束；具体 UI 要求：

- 首屏是项目管理首页，真实数据为空时为空，不默认进入“个人网站”等示例项目。
- 示例入口独立，顶部明确模式。正式模式不得把样例任务/待处理混到用户项目。
- 软件左上角统一返回按钮；任务回流程/项目工作区，项目回首页，首页禁用；不在任务标题区再放重复返回。
- 会话正文 15px、发送者 14px、代码/工作依据 14px、辅助操作不低于 13px。
- Codex 全部使用 GPT/OpenAI 结形图标，Claude/DeepSeek 对应图标；保留文字，不用模型假名。复用预览 SVG 需保留 Lobe Icons MIT 许可。
- 弹窗关闭、提醒关闭和缩放按钮 44×44px 点击区域、24px 符号；保留可访问名称、焦点和 Escape。
- 通知不抢焦点，关闭通知不解决事项。未知模型与不支持能力按事实显示。
- 不将 Bearer 令牌放 localStorage、日志、截图或 URL；沿用内存连接管理。

## 4. F01：真实项目首页与项目上下文

**Consumes（已实现）:** `ApiClient.projects(signal?)`、`project(id,signal?)`、`createProject({name,description?},key,signal?)`、`updateProject(id,{expectedVersion,name?,description?},key,signal?)`。精确签名以主项目 api.ts 为准。

**Produces:** 可以刷新重读的项目首页；明确 projectId 的路由/选择上下文；新项目空工作区；原可信项目仍能进入受支持任务链路。

- [ ] 读 B03–B05 契约、前端实际实现和用户最新设计反馈，记录当前是替身还是 HTTP。检查 vendored 三文件差异，在后端未写入时同步完整 B05；记录源文件 SHA-256。
- [ ] 先为项目切换、迟到响应、编辑冲突建立必要状态测试；确认测试在功能未实现时失败。测试断言按行为，不镜像组件内部变量。
- [ ] 接项目列表与按需详情，显示 loading/空态/失败/离线/重试，禁止硬编码项目名称、任务数、假进度。列表只有 id/name 时不编造 description 或执行状态；详情按需读取，避免无界并发 N+1。
- [ ] 实现创建和名称/说明编辑：遵循名称非空且 ≤200、说明 ≤8000、版本+显式幂等键；请求中防重复提交。成功重读详情，失败保留用户输入。
- [ ] 网络结果未知时不悄悄换键重发创建；同一操作同载荷保留键，可显式核对/重试。更改载荷必须新键。
- [ ] version_conflict 时重新读取最新版本，显示冲突并保留草稿供用户比较，不自动用新版本覆盖重发旧载荷。
- [ ] projectId 切换取消旧请求、断开旧订阅/核验响应归属；不把 bootstrap.project 当用户始终选中的项目。
- [ ] 配置项目执行能力与新组织项目分开。新项目空工作区能展示元数据/接入入口；没有流程接口时显示清晰空态，不给假启动按钮。
- [ ] 浏览器验证创建两个项目、分别编辑、刷新重读、项目切换、断网/恢复、版本冲突、返回行为；检查无跨项目数据混入。

## 5. F02：只读仓库接入、确认与旧链路联调

**Consumes（已实现）:** `inspectProjectRepository`、`confirmProjectRepository`、`projectRepository` 及 ProjectDetail.execution；B04 `overview/attention/acceptance/recovery` 和旧任务接口。

**Produces:** 完整真实“提交路径 → 只读检查 → 显式确认基线 → 保存关联”流程；能力驱动的设置页/任务入口；B05 HTTP 浏览器验收报告。

- [ ] 为检查过期、仓库变化、未提交排除、能力禁用建立呈现/状态测试，再实现对应 UI。
- [ ] 使用系统权限所允许的路径文本输入；网页尚无原生选择目录能力时不得伪装真实文件选择。只在用户提交后调用检查。
- [ ] 展示真实路径、attached/detached/unborn、HEAD、staged/unstaged/untracked/conflicted 计数及 worktree；检查有界拒绝不能展示为干净。
- [ ] 无 commit 基线显示不能确认；dirty 仓库可按 B05 确认该次完整 HEAD，但必须显式承认未提交改动排除，不能默认勾选用户同意。
- [ ] 确认提交 expectedVersion、inspectionId、baselineCommit、acknowledgeUncommittedExcluded:true。保持该次检查上下文，不能让手改 commit 绕过。
- [ ] inspection_stale/expired、repository_changed 要求重新检查；不能使用旧检查键获取“新结果”。扫描失败/超时保留路径输入并给准确下一步。
- [ ] 成功后重读项目版本/关联；展示“确认当时事实”而不是“当前仓库一直干净”。普通项目卡片不泄露专用接口才返回的完整路径。
- [ ] 按 execution.supported/reason 禁用未绑定执行，展示“仓库已关联，仍需受支持执行绑定”。supported 不等于登录、额度或实际运行成功。
- [ ] 对旧可信项目复测任务准备/运行/事件/快照/真实检查/接受；如接总览与待处理，用真实 API，分页取完或展示下一页，不能把前50项计数冒充全量。
- [ ] availableActions 按实际值 start/feedback/snapshot/check/cancel_check/prepare_workspace/edit/interrupt/accept/recover_check 等白名单呈现；未知动作不默认可执行。recoverable=false 不制造恢复按钮。
- [ ] 接受用 AcceptanceSummary.status，检查用 validity；反馈或外部变化后重读，不能因 reducer 失去增量事件而丢失失效原因。
- [ ] SSE 断开按最后 seq 恢复、去重、缺口重读；离开页面释放订阅。项目/任务变化保留各自草稿和阅读位置，不能串话。
- [ ] 执行 `npm run typecheck`、`npm run build` 和现有相关测试，处理真实失败；浏览器在 1440×900、1280×800、约800px窄窗口检查可读性/弹窗/返回。
- [ ] 在真实 HTTP fixture 环境验证检查后修改仓库→确认被拒绝，刷新/服务重启重读关联，旧任务接受失效。服务重启由环境拥有者执行或使用自己的可恢复测试环境。

## 6. Review Focus

1. 迟到请求覆盖新项目：F01 测试切换后旧响应被忽略。
2. 超时写入成功但客户端误以为失败重复创建：F01 测试保持操作键及明确重试。
3. 同名项目路由串线：F01 全部按 ID，测试同名不同 ID。
4. 关联 GET 是历史事实却渲染成当前检查：F02 时间与刷新入口测试。
5. 未提交勾选/能力门禁被省略：F02 不能确认或启动的 DOM 断言及服务真实拒绝。

## 7. 后续前端批次（不是本轮直接实现）

### F03：流程图与批准

依赖 B07 发布：角色/成员/负责人、层级与依赖、草案版本、部分批准接口。

工作：图/树双视图、节点两行身份/状态、原因和待处理标记；手动建节点/改依赖，审阅受影响节点；批准指定草案版本和选中子集。图拖动是布局还是业务改依赖需区分。没有依赖数据不从对话文本猜关系。

验收：循环和跨项目依赖错误可见；未批准不能启动；批准旧版本拒绝；部分批准规则与后端一致；返回图保留视口；图可键盘访问或有等效树视图。无图依赖先评估已有能力，新增库需明确批准。

### F04：节点工作区与多工具

依赖 B07/B08：任务与节点绑定、实例能力、真实工具/模型、审批契约。

工作：同视图目标/会话/成果/worktree，默认单会话、临时并排第二会话；按 projectId/taskId 保存草稿、滚动、订阅。显示每轮实际模型；换工具有交接与上下文边界。配置多实例，不假设同一工具只有一窗口。

验收：两会话事件隔离；真实/未知状态清楚；中止确认、审批只有服务提供时显示；刷新重读、断线恢复、长消息与双栏不缩成不可读；IDE入口只有宿主支持时可用。

### F05：待处理、交接、并行与恢复

依赖 B09–B11。交接草稿编辑后显式发送，固定接收任务/版本/文件/未解决事项；展示发送记录和失败重试。队列区分批准/依赖/资源/运行，不能把排队当执行。角落提醒不抢焦点，关闭不清除事实标记，重连不得重复弹历史事项。恢复按后端 recoverable 展示，未知结果保留保护；归档不等于删除代码。

验收：两个项目/同一工具多个任务隔离；交接同键不重复发；依赖满足但未经批准仍不启动；关提醒后事项仍在；未知结果不能前端“确认成功”解除。

### F06：集成和最终验收

依赖 B12。界面分开展示本轮接受有效性、具体来源 commit/快照、集成目标分支、冲突、联合检查、最终验收。明确展示用户将批准的计划、命令与来源；不要把旧成功检查贴到新集成产物。

验收：来源接受失效、目标变化、冲突、取消/失败/超时均有出口；重启可追溯；没有真实检查结果不能标通过；不自动推送。

### F07：桌面和成品体验

依赖 B13–B14 选定并验证宿主。首次配置不让终端用户手填内部令牌，失败保留诊断入口；前台提醒/后台系统通知定位任务；运行中退出询问后台继续或停止后退出，等待真实停止结果。对 Windows/Linux 安装、升级和备份恢复做真实演练；web fallback 不假装有托盘和系统进程控制。
