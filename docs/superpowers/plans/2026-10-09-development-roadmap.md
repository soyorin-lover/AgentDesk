# AgentDesk 前后端后续开发总路线

> **For agentic workers:** 实施时使用 superpowers:executing-plans，按任务逐项完成；确有独立子任务时可用 superpowers:subagent-driven-development。本文件用于分批交接，不是要求一次完成整个系统。

**Goal:** 将已确认的项目管理 → 分工流程 → 多 Agent 会话 → 成果确认 → 交接与集成做成可安装、可追溯的开发者软件。

**Architecture:** 前端展示和提交用户意图；后端保存事实、版本、授权及执行证据。项目组织空间、仓库关联、执行绑定、流程批准、任务执行、成果接受和代码集成是不同对象，不相互冒充。

**Tech Stack:** 已有 React/TypeScript 前端；Node >=24.17.0、TypeScript、SQLite、Git 后端。现阶段复用依赖，新增依赖或桌面宿主选型另行说明依据。

**Spec:** [最新产品决定](../../PRODUCT-DECISIONS-2026-10-09.md)、[界面设计基线](../../../DESIGN.md)、[第 5 批接口](../../BACKEND-BATCH-05-API.md)。

## 1. 如何交给两个对话

- 前端对话：发送 [前端任务书](2026-10-09-frontend-development.md) 最后的启动提示词。立即执行 F01–F02。
- 后端对话：发送 [后端任务书](2026-10-09-backend-development.md) 最后的启动提示词。立即执行 B06。
- 两条线可以同时开始：前端消费已完成的 B05；后端新增 B06。前端不得依赖尚未冻结的 B06 接口。
- 一批完成后报告、保存交接；后续批次按下表推进。不能因看到完整路线就擅自一次改完全部模块。
- 本次没有新建或给其他对话发送消息，文档由用户选择分发。

## 3. Global Constraints

- 面向开发者；目标 Windows / Linux；执行使用跨平台路径和参数数组。
- 创建 AgentDesk 项目不等于创建仓库、Agent 原生项目、会话或启动任务。
- 原工作区的未提交代码不得被 reset、stash、自动 commit 或覆盖；新 worktree 只使用明确基线。
- 负责人可以提议，用户批准后才执行；批准、依赖就绪、开始执行是独立事实。
- 执行成功、检查通过、成果接受、代码集成和最终验收分别记录。
- 工作区属于任务；同工具可有多个会话；上下文通过显式交接，不默认共享。
- 真实模型探针单列，先说明额度/操作范围并取得该次授权；其他批次使用无模型 fixture。
- 不自动推送、部署、清理现有工作区或提交全部未跟踪文件。源码仓库当前无首次提交，不能强行依赖 HEAD 建 worktree。
- 当前两个对话分别只写分配的目录；原文件有别人修改时保留并适配。禁止同时修改同一公共契约文件。

## 4. 所有权与契约发布

| 文件/资源 | 唯一写入方 | 另一方如何配合 |
| --- | --- | --- |
| 主项目 `src/backend/**`、`src/codex/**`、`src/client/**`、后端测试与脚本 | 后端对话 | 前端只读，问题写前端交接 |
| 前端 `src/**`、前端配置/测试和 vendored 副本 | 前端对话 | 后端提供契约，不跨目录直接修组件 |
| 主项目 `docs/BACKEND-BATCH-XX-API.md`、结果和后端交接 | 后端对话 | 前端读取，不就地修改接口定义 |
| 前端工程 `docs/FRONTEND-FXX-RESULTS.md`、接口缺口 | 前端对话 | 后端读取并在下一契约批修复 |
| 主项目根配置/锁文件、HANDOFF.md | 后端对话，本轮需要时修改 | 前端不能为同步客户端改主项目配置 |
| 主项目 DESIGN.md、HTML 预览 | 当前产品/UI 评审对话 | 执行对话只读；细节建议在各自结果中记录 |
| 当前规划文件 | 本次协调文档，视作只读交接 | 执行记录放各批结果，不并发改总路线 |
| 运行服务、库、令牌、端口 | 启动该环境的对话 | 记录环境身份；不结束别人进程，不写入另一方运行库 |

每个后端批次先写 API 契约，明确新增与兼容字段、错误、版本/幂等、动作、事件和能力。标明“草案”直到实现测试完成；发布时记录相关文件 SHA-256，或有提交后使用 commit。前端只同步完整发布的 api.ts / execution.ts / types.ts，不在后端写入过程中复制半份类型。

禁止用会议约定代替真实可读契约，也禁止对未来接口预先硬编码“成功”。没接口时显示未支持状态或独立标识样例；不发明服务端响应。

1. 切换项目后旧响应、旧 SSE、草稿与游标串入新项目：F01/F04 负责请求取消、身份核对和隔离测试。
2. 关联后、绑定后仓库或基线变化，旧任务被悄悄换代码：B06/B12 固定引用并再验证，前端显示过期和可恢复步骤。
3. 图编辑改变已经批准的内容或绕过直接启动接口：B07/B10 服务端验证授权范围，部分批准必须有依赖闭包规则。
4. 执行器断线/崩溃结果未知却显示完成，或中止后仍有子进程：B08/B11/B13 验证退出证据和恢复能力，不删除隔离保护。
5. 检查/接受曾经有效但新反馈、外部修改或集成目标变化后继续误用：F04/B12 重读摘要并绑定具体版本。

## 7. 联调环境与验收格式

开发期可以使用内部连接设置，最终产品不要求用户复制 localhost/令牌。由后端持有独立 fixture 服务，令牌只在忽略的本地文件或内存，不写文档/截图/浏览器存储。前端可在自己测试里启动临时服务，不能结束共享服务。

`scripts/integration-server.ts` 当前每次启动生成新库，不能用于“重启后数据保留”的证据。持久化验收使用独立临时持久数据库及可复用的同一环境配置；由后端提供明确 restart/resume 方法，不覆盖已用环境。任何新增启动选项必须有环境身份/路径验证测试。

每批结果固定包含：

1. 实施边界、实际文件、契约版本/校验值。
2. 测试命令和实际通过/失败/跳过；不存在的 build/lint 不声称执行。
3. 模式分别写清：前端 fetch 替身 / 真实 HTTP+Git+SQLite 无模型 fixture / 真实工具模型。
4. 浏览器尺寸、实际 DOM 操作和错误分支；后端测试不替代前端浏览器验收。
5. 未支持/未验证、迁移影响、服务是否更新、保留的数据和下一步。
