# AgentDesk 后端开发任务书

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans，逐任务实施验证；独立、有清晰所有权的测试或审查才使用 superpowers:subagent-driven-development。

**Goal:** 先让明确授权的多个项目按固定基线执行，再逐批实现角色流程、多工具、并行交接、恢复、集成和成品化。

**Architecture:** 延续 Node/SQLite/事件与服务端能力判断。B05 组织项目和仓库关联保留；新增执行绑定必须来自受信配置授权，并被具体任务固定引用。不要把浏览器传来的路径、命令或 trusted=true 当权限。

**Tech Stack:** Node >=24.17.0 / TypeScript / SQLite / Git，现有 EngineAdapter 和 Codex 协议适配；不引入新的运行框架。

**Spec:** [总路线](2026-10-09-development-roadmap.md)、[最新产品决定](../../PRODUCT-DECISIONS-2026-10-09.md)、[B05 API](../../BACKEND-BATCH-05-API.md)、[B05 结果](../../CODEX-BATCH-05-RESULTS.md)。

## 1. 本轮 B06 的边界

立即实施 **B06：显式受支持多项目执行绑定 + 按任务固定仓库基线**。先写短技术计划和 API 草案，完成代码/回归/真实 Git+SQLite+HTTP 验证后发布正式契约。

本批不同时做完整流程图、Claude/DeepSeek、并行、任意未知进程恢复、集成、桌面宿主。保留全局串行，不把两个项目可以分别运行表述为并行已实现。

未提交改动的本批处理明确为：读取和告知、保留原目录、使用已确认 commit 排除未提交内容；用户需要纳入时在 IDE/终端显式处理提交后重新检查确认。不得自动保存为 stash/commit 或将工作区字节复制成不明基线。以后增加软件内保存功能另立契约和批次。

## 2. Global Constraints

继承总路线约束，另外：

- B05 `/projects` 简表、已有任务、版本/幂等/事件/接受失效规则兼容；新能力只增量扩展。
- 关联仓库不授权执行，执行绑定不自动创建 worktree/调用模型；启动仍需显式任务命令。
- 真实仓库身份、绑定修订与任务基线固定，外部变化和重新绑定不得偷换已有任务代码。
- 原可信配置项目必须可继续执行，不重新编号任务、不篡改旧事件和有效证据。
- 不允许 HTTP 直接提交 executable、shell command、PID 或任意 cwd 绕过配置。检查预设仍为服务受信配置。
- 不默认调用真实模型；fixture 通过 EngineAdapter 注入，生产模式不得静默回退 fixture。
- 不修改前端目录、前端 vendored 副本、HTML 预览和 DESIGN.md。接口文档与主项目公共客户端由后端唯一写入。
- 运行数据库、凭据及别人启动的服务不动；所有迁移/回归先临时数据库。源码未首次提交，不自动提交/推送。

## 4. B06 Task 1：授权模型与契约

**Consumes:** B05 ProjectDetail / RepositoryAssociation、配置 ProjectConfig、旧 ProjectRegistry 与 BackendService.open。

**Produces:** 可测试的受信授权策略和 B06 API 草案；新增字段/错误/事件及兼容策略，不能只写“支持多项目”。

- [ ] 核对 service/registry/adapter 中所有单项目假设：准备、执行 cwd、快照、检查、接受、重启恢复、租约/quarantine、bootstrap 与项目查询，列出改动点。
- [ ] 将“组织项目”“已确认关联”“允许执行的仓库配置”“具体执行绑定修订”分开。开发期授权来源使用启动时本机受信配置；HTTP 只能请求绑定已登记的授权项，不能自行注册任意路径为可信。
- [ ] 定义配置条目唯一身份、canonical path/gitDir/commonDir 核对规则、worktreeRoot 和检查预设范围。冲突配置启动失败，不能随机取第一项。
- [ ] 定义绑定命令的显式确认正文：项目版本、已确认关联/基线引用、受信授权项引用。服务端重新核验，不能仅相信关联已经保存。
- [ ] 明确建议 `GET/POST /projects/:id/execution-binding` 只是本计划的候选接口，必须在 B06 API 文档冻结精确请求/响应后供前端使用。未发布前不得声称存在。
- [ ] 扩展 ProjectDetail.execution 的实际能力/原因及 repositoryAssociationUsed，兼容 B05 原 false 类型，新增字段用安全可选/可辨分支；supported 不代表登录或额度。
- [ ] 先写失败测试：未授权路径即使关联成功仍拒绝绑定/执行；两条显式受信仓库可以分别绑定；配置冲突拒绝；旧单项目继续工作。

## 5. B06 Task 2：绑定持久化与固定任务依据

**Produces:** 可重启重读的绑定修订；新任务保存 projectId、binding revision、仓库身份/基线所需引用；旧任务有明确兼容读取路径。

- [ ] 先测试 expectedVersion 并发只有一次成功，同键同载荷不重复绑定，同键异载荷冲突，确认后重启保留。
- [ ] 实现绑定保存与项目版本更新的事务。普通列表/总览不泄露完整路径，专用认证接口才返回用户需要的绑定信息。
- [ ] 新任务创建时固定绑定修订和完整 baseline commit，后续步骤不能仅通过 projectId 取“最新仓库”覆盖旧引用。
- [ ] 关联重新确认/基线改变后，新任务使用新批准依据；已有准备/运行/接受任务保持原引用。活动任务存在时不允许危险换绑；若要换授权项，本批可明确拒绝并给原因，不必实现解绑清理。
- [ ] 重启校验旧绑定、配置和实际仓库身份；授权项缺失/改指向时报告不可用，不静默认领另一仓库。代码基线 commit 存在性必须重新验证。
- [ ] 非破坏地兼容旧任务/数据库：只补足可证明的引用，不能从当前 HEAD 推测历史基线；没有证据则不可执行/待恢复，不重写历史事实。

## 6. B06 Task 3：准备和执行按项目正确路由

**Produces:** 两项目各任务独立 worktree，使用固定基线；准备/快照/检查/接受始终对同一受支持身份操作。

- [ ] 写真实 Git 测试：源仓库 A/B 有不同文件内容/commit，任务 worktree 只能来自各自绑定；原仓库脏文件保持字节和 index/HEAD 不变。
- [ ] 按绑定选择仓库与 workspaceRoot，验证目录归属、marker、commonDir、分支和基线，重复准备幂等；拒绝外部改 marker、junction 重指向和身份不符。
- [ ] 保留固定 commit：源 HEAD 在已绑定后推进，不自动把旧任务切到新 HEAD。说明 HEAD 合法推进与仓库身份变更的不同处理；只有显式重新检查/确认产生新的任务基线。
- [ ] 将执行 cwd、快照 Git、真实检查、接受扫描和恢复查验改为使用任务固定引用，不能执行 A 却扫描/检查 B。
- [ ] 保留全局 busy/未知结果隔离保护；跨项目也不能借新路由绕过 needs_recovery。不得为让测试跑通删除租约/quarantine。
- [ ] 运行两任务 fixture，验证事件、会话、文件、快照摘要、检查、接受与外部修改失效隔离。模型名明确 deterministic-fixture。

## 7. B06 Task 4：真实 HTTP 和前端联调交付

**Produces:** 冻结的公共客户端、B06 API、带环境身份的联调方式；前端可随后接绑定。

- [ ] HTTP 与客户端测试覆盖 Bearer/Host/Origin、输入字段拒绝、能力原因、版本/幂等错误、取消等待/响应未知，不让新端点成为绕过旧门禁的路径。
- [ ] 新能力在服务端执法，不只返回一个可被忽略的 supported=false。直接 POST task/prepare/start 同样验证绑定。
- [ ] 扩展 fixture 环境供两个项目绑定/任务演练，默认无模型。明确允许的前端 Origin，不硬编码为允许所有来源。
- [ ] 如提供重启保留模式，使用同一受验证数据根、库、源码/worktree 和令牌的可恢复配置，保持旧启动默认行为；不能声称原脚本每次新库是持久化证据。
- [ ] 发布 API/RESULTS 并记录 api.ts、execution.ts、types.ts 的 SHA-256。同步方式为前端在发布后复制；后端不修改前端副本。

## 10. 后续后端批次（按依赖单独实施）

### B07：角色、负责人、节点与批准

数据范围：成员/工具实例引用、可复用角色、每项目负责人、节点目标与验收条件、父子层级、独立依赖边、流程草案修订、用户批准记录和批准子集。

层级树表示工作拆分，依赖 DAG 表示执行顺序，两者不能混为一组边。服务端拒绝跨项目引用、循环、悬空依赖。节点是组织对象，可关联执行任务；不要把 UI 状态直接塞入旧 TaskStatus 破坏兼容。

先支持用户手动草案；负责人生成文本建议不等于任意 JSON 自动执行。批准绑定精确修订和选中节点、执行配置与依赖。部分批准必须明确：未批准依赖使节点阻塞或拒绝该子集，不能自动扩充批准范围。变更已批准目标/实例/基线/依赖要新草案并显示影响。start/feedback 等直接端点也须验证受管节点授权，不可只靠 UI 隐藏。旧非流程任务用明确兼容模式，不反推“用户已批准”。

证据：批准/修订持久重读；并发版本冲突；部分批准、依赖闭包、环、越权、旧任务回归；“执行成功后待人工确认”与检查/接受区分。定义节点完成依据与现有 snapshot/acceptance 的映射并测试失效，不靠进程退出自动完成节点。

### B08a/B08b/B08c：实例和多引擎

B08a 先抽取确有必要的实例/能力注册、每任务原生会话引用、每轮实际模型、工具身份与事件规范化，Codex 不回退。然后 B08b Claude、B08c DeepSeek 各自独立批次。

各工具先核验本机实际安装版本和官方协议，选择受支持机器接口。不能以 OpenAI-compatible 模型 API 当作完整 Coding Agent 适配，不能解析 TUI 文本作核心接口。对 start/continue/interrupt/approval/recovery 支持矩阵分别标明未支持、已适配未实测、真实验证，实例登录/额度未知不伪装在线。

每引擎先 fake transport 协议测试，再在明确授权的小额临时仓库验证真实会话、反馈、中止、工具调用/审批、断线/错误。若原生恢复不支持就显式报告，不伪迁移别家会话。真实探针凭据/原始敏感日志不入库。

### B09：显式交接与项目背景

保存用户确认的项目现状/目标/文档引用，与 Agent 分析待确认结果、产品实际执行证据区分。交接 draft 包含源任务/轮次、目标任务/会话、具体版本/文件引用、约定与剩余问题；编辑后显式确认发送。

对发送行为幂等并保存投递事实；源版本过期、目标被替换、目标忙碌有明确处理。只有协议证据才能称送达/已读取，不能把已入本地队列称为对方看过。负责人起草与发送权限分开。测试跨项目拒绝、重复发送、过期、崩溃重读、长内容限制，不隐式共享整段历史。

### B10：并行与受约束调度

在 B06/B07/B08 基础上将全局锁拆成项目/任务/执行资源约束，不先删 busy()。声明并分配模型并发配额、端口、数据目录/数据库及检查资源，保留 quarantine 所保护的具体资源。

执行资格至少同时满足：指定修订已批准、依赖成果当前有效、绑定有效、资源已分配、任务不在未知结果状态。用户可批准范围内调度；不把依赖满足当无限授权。测试同工具两会话并发、争用排队、公平/饥饿边界、取消队列、依赖失效、重启不重复派发。worktree 是代码隔离，不宣称安全沙箱。

### B11：恢复、归档与保留

为 workspace preparing/模型结果未知/检查未知分别建立持久进程与租约证据和恢复命令，Windows/Linux 行为各验。不接受客户端 confirmed=true、PID 或结果作为退出证明。不重放结果未知的模型请求；不删除未知进程保护以“解锁”。

归档保存历史、草稿和成果；工作区回收另需显式检查无活动/未知进程、无未提交改动、归属明确且保留必要证据。第一阶段可只归档不回收。故障注入覆盖启动前后、持久退出前后、数据库写失败、服务崩溃和客户端断开。

### B12：专用分支集成与最终验收

输入是当前有效的具体接受记录及来源代码依据，不是任务名。明确 snapshot digest 如何变为可集成 Git 内容：若执行成果未提交，生成受用户批准的不可变 Git 产物/提交或受控补丁，保留未跟踪/二进制/不支持文件边界；不能直接 cherry-pick 一个不存在的 commit，也不能拿随后变化的 worktree 替代已接受内容。

用户审阅集成计划后在专用集成 worktree/分支执行。目标 HEAD 变化、冲突、内容不支持、取消/检查失败都有独立结果和安全出口；不自动切换用户工作分支。联合检查绑定实际集成产物，最终验收记录绑定其 commit/check evidence。测试源接受失效、目标变化、冲突、重启和幂等；不自动 push/deploy。

### B13：宿主与生命周期

另做桌面技术选型说明，评估已有前后端复用、Windows/Linux、通知、托盘、进程监督和更新需求后选型，不在 B06 顺手引入 Electron/Tauri。

服务启动与本地认证由宿主管理，最终用户不用复制内部令牌。运行中关闭选择后台继续或停止后退出；停止需等待真实结果并保留代码，不能仅 abort HTTP 请求就声称工具退出。前台/后台通知按真实权限和运行状态，点击定位具体项目任务，拒绝权限有降级。IDE/终端打开入口限制为已验证任务 worktree。

### B14：安装、升级、备份与最终回归

明确 Node/Git/工具依赖的分发或检测方式；运行数据与安装目录分离。迁移失败可恢复，备份一致且凭据分离，恢复后未知执行不自动重放。建立可审查版本基线/提交策略，不自动首次提交全部文件。

Windows/Linux 干净环境真实安装→创建/接入→批准→多工具任务→交接→并行→成果确认→集成→联合检查→最终验收→重启/备份恢复。真实工具证据与 fixture 分开，报告未覆盖平台/能力；达到该闭环才称首版交付。

## 11. 可以直接复制的启动提示词
