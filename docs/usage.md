# 使用指南

本指南描述 Windows 本机串行 Codex 流程。先按 [README](../README.md) 安装前端依赖；仅查看示例可直接打开 `/#/preview`。

## 准备仓库与配置

目标仓库需要至少一个 Git commit。首次配置建议使用干净的小型示例仓库。工作区根目录必须与目标源码和 AgentDesk 目录互不重叠。

在 AgentDesk 根目录复制 [配置模板](../config.example.json) 为 `.agentdesk/local-backend.json`，填完所有占位符。相对路径按启动时的工作目录解释，下面命令均从根目录运行。

| 配置项 | 含义 |
| --- | --- |
| `projects` | 本机允许执行的来源仓库；基础配置使用一个项目，含稳定 ID、名称和绝对路径 |
| `workspaceRoot` | 独立任务 worktree 根目录，使用绝对路径 |
| `database` | SQLite 路径，必须在 AgentDesk 的 `.agentdesk/` 内；不要复用其他来源仓库的旧库 |
| `port` | 后端端口，模板为 4317；0 表示分配空闲端口 |
| `allowedOrigins` | 实际前端来源，localhost 与 127.0.0.1 不同，不带末尾斜杠 |
| `checkPresets` | 本机受信检查命令、参数、时限与输出上限 |
| `transport` | Codex 上游传输；模板使用本轮验证过的 `http` |
| `codexBinary`（可选） | Codex 可执行路径；省略时也可设置 `CODEX_BIN`，否则按默认命令查找 |
| `model`（可选） | 请求的模型配置，不是实际物理模型证明 |

JSON 路径可用正斜杠，或将反斜杠写成双反斜杠。`node -p "process.execPath"` 可查询 Node 可执行文件路径。

模板的 `node --version` 只验证命令可执行。改为目标项目实际测试，例如可执行文件为 Node 绝对路径，参数为 `["--test", "normalize-title.test.mjs"]`。检查在任务 worktree 中运行，使用参数数组，不展开 shell 通配符；Windows 不支持直接将 `.cmd`/`.bat` 作为检查预设。

进阶多来源授权使用 `executionGrants`，由本机配置登记受信仓库。网页只能绑定匹配的来源和基线，字段以 [启动入口](../src/serve.ts) 和 [执行绑定](../src/backend/execution-bindings.ts) 为准；基础入门不需要手写进阶配置。

## 启动并连接

前端与后端分别运行：

```powershell
npm --prefix web run dev -- --host 127.0.0.1 --port 5331 --strictPort
```

```powershell
npm run serve -- --config .agentdesk/local-backend.json
```

后端输出 API 地址和访问令牌文件路径。在前端连接页填写地址和该文件中的令牌。令牌不要写进源码、URL、截图或问题报告；浏览器客户端在内存中持有它。后端重启后令牌可能改变，需要重新连接。

服务仅监听本机回环地址。HTTP API 与 Codex 上游连接是两回事：`transport=http` 控制后者，临时关闭 WebSocket 与请求/流重试，不改全局 Codex 配置。

## 安排并执行任务

1. 在项目入口查看配置的项目，或创建项目空间后检查已有仓库。
2. 确认来源与 commit。未提交修改不自动带入 worktree；要使用当前修改，先审查并保存为 commit，再明确绑定新基线。
3. 仓库关联与执行授权分开。新建项目需要匹配本机允许的来源，不能仅靠输入任意路径执行。
4. 在蓝图填写目标、验收条件、角色、成员和 Codex 实例，保存后单独批准节点。
5. 建立执行记录，准备工作区，核对来源、固定 commit 和执行对象后显式开始。

保存或批准不会自动调用模型。修改计划会撤销旧修订的后续授权；旧任务保留历史输入。

进入工作台查看消息、活动与运行状态。一次任务可以有多个 Run；首次结束后可在“要求修改”中追加反馈，必须续接已证明归属的原生会话。缺少证明时拒绝，不自动另开线程。

202、模型的一句“完成了”或断连都不是成功证据。关闭页面不会取消后台运行，返回时重新读取持久记录。服务全局串行，有执行、检查或未知结果阻塞时不能另起任务绕过。

## 审查、检查与接受

生成快照并查看 Diff，确认只改了预期文件。选择真实检查预设，等待退出结果，确认检查仍对应当前文件。

| 显示 | 含义 |
| --- | --- |
| 执行完成 | Agent 轮次确定结束，尚不能据此接受代码 |
| 检查 passed/current | 检查通过且对应当前内容；仍需判断检查是否有意义 |
| 检查 stale | 内容或关联已变，旧通过不能用于当前成果 |
| 成果已接受且有效 | 用户接受了具体快照，没有自动合并源码 |

产品不强制检查通过才能接受，建议先完成有意义的检查与审查再接受。继续执行或外部修改可能使旧接受失效。代码仍在任务 worktree，自动集成尚未交付，需自行审查并决定如何用 Git 整合。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 连接失败或 401 | 核对 API 地址与当前令牌，不混用不同数据库的服务 |
| Origin 被拒绝 | 配置实际前端来源，注意 localhost 与 127.0.0.1 |
| 端口占用 | 更换本轮端口，不终止不属于本轮的服务 |
| 409 | 重新读取状态、核对冲突、保留草稿，不静默换版本重发 |
| Codex 找不到或启动失败 | 核对路径、登录和 CLI 版本，先读诊断而不是重发 |
| readOnly | 修正启动环境；适配器要求 workspaceWrite，不能放宽校验假装可写 |
| 未知/待恢复 | 保留记录并核查，不等于可安全重试，不手改数据库清除门禁 |
| 检查不可用/失败 | 核对可执行文件、参数、工作区、时限和输出，区分失败与过时 |

实际故障与验收边界见 [验证指南](verification.md)。
