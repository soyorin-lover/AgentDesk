# 第 1 批：Codex 最小接入验证

## 目标与停止条件

实现一个独立命令行验证器，证明 Windows 上可以通过 App Server 与真实 Codex 会话通信。完成并报告证据后停止，不搭建整个后端。

## 已验证基线

2026-10-08 已验证本机 Codex 0.162.0-alpha.2 可启动 App Server，通过 stdio 完成 initialize / initialized 握手；尚无模型执行证据。

## 实现范围

- Node.js / TypeScript 验证器及有意义的协议处理测试。
- 子进程以参数数组启动，默认 stdio；二进制位置支持配置，不提交机器专用路径。
- JSONL 增量缓冲、请求响应匹配、服务端请求、事件分发、超时和退出处理。
- 保存会话与运行标识及脱敏验证摘要；保存在忽略的运行目录。
- 只在专用示例仓库中验证文件修改，不对主项目启动测试性改写。

## 按顺序验证

1. 启动与初始化，失败能清晰退出。
2. 创建会话并指定工作目录；发起最小任务，接收文本事件及最终状态。
3. 在示例仓库修改一个指定文件，读取真实 Git diff。
4. 发起第二轮交流验证上下文；关闭后重新连接并恢复会话，验证后续轮次。
5. 长任务中补充指令、中止当前轮次；核对最终事件。没有已验证的中止结果时不得声称完成。
6. 在当前版本支持且策略允许的条件下触发、接受和拒绝审批；未能触发如实标记。
7. 两个独立工作区中的会话并行执行，各自只产生预期文件变更；记录账户或环境限制。

## 验证要求

协议测试覆盖消息分片、错误响应、超时、进程提前退出与重复请求处理；模拟测试不能替代真实调用。
退出后的进程与工作区需检查，不自动删除未保存改动。
运行会调用真实模型并消耗账户额度，使用最小任务；不硬编码模型名称或推断账户权限。
Linux 在后续独立环境或 CI 验证；Windows 通过不能代表 Linux 已通过。

## 交付

可执行验证器、使用说明、测试结果、真实接入验证矩阵、已知问题及给 Claude 的能力更新。
