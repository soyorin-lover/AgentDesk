# 第 3 批：可持续使用的后端

状态：已实施并验证，结果见 [CODEX-BATCH-03-RESULTS.md](CODEX-BATCH-03-RESULTS.md)，公共契约见 [BACKEND-BATCH-03-API.md](BACKEND-BATCH-03-API.md)。本批只改主项目后端、公共客户端与文档，不改 Claude 页面，建立下面这条链路：**登记一个真实源码项目 → 为不同任务准备隔离工作区 → 串行执行/反馈 → 查询改动 → 运行检查并辨认过时结果 → 人工接受。**

## A. 项目、工作区与多任务

项目根路径和任务工作区根目录由可信本地配置指定，浏览器只能提交 projectId，不能任意选择文件系统路径。先支持一个登记的源码项目，提供项目列表接口，模型中保留项目身份。源码仓库必须有有效 HEAD；首次登记要求干净，发现未保存修改只报错，不清理、不暂存、不提交。本项目当前没有首次提交，不能为了演示自动提交全部源码；测试使用独立 fixture 仓库。

新项目模式中，创建任务先保存任务；显式“准备工作区”动作创建对应 Git worktree 和应用生成的 codex/task-<id> 分支，记录固定 baseHead。每项任务都有自己的工作区与 Codex 会话。准备成功后才允许启动，availableActions 如实表达。工作区根目录不得在源码或 AgentDesk 主项目内，也不得是它们的祖先；检查真实路径、Windows 大小写及 junction/符号链接，不能只比较字符串。

工作区创建是外部副作用：先持久化准备意图，再执行 Git，最后记录结果。重复幂等请求不得再次创建；路径或分支冲突不能复用陌生目录。重启遇到未完成准备应核实归属，不能自动删除、强制重置或假装成功。应用自有 Git 工作区创建禁用 hooks；Git 使用参数数组。

允许同一项目多项任务，保留全局串行执行，不做队列或并行调度。活动模型运行或无法确认退出的运行继续阻止新执行。反馈、快照、接受、事件、游标及租约必须按 task/workspace 隔离，绝不能只删除当前单任务限制后共享 cwd。

旧配置 workspace 模式及旧数据库继续可用，保留原任务、会话与接口。新增项目模式使用另一份本地测试配置和数据库验证，不默默迁移正在使用的数据。若需 schema 升级，先用旧库 fixture 验证升级与备份策略，再提供明确说明。默认不自动回收 worktree、删除分支或清理旧库。

## B. 真实检查与过时结果

新增独立于模型 Run 的 CheckRun。检查预设只由可信本地配置提供：id、名称、可执行文件、参数数组、超时及输出限制。浏览器只选 presetId，不提交 shell 命令。初版可用 Node 测试或 git diff --check 作为 fixture；不自动安装依赖、生成项目测试脚本或扫描后执行未知命令。使用 shell:false；Windows .cmd/.bat 无安全支持时明确 unavailable，不能退化成拼接 shell 字符串。

检查绑定 taskId、runId、snapshotId、contentDigest，记录开始/结束时间、退出码及有界输出。执行结果（passed/failed/cancelled/timed_out/needs_recovery）与有效性（current/stale）分别表示。只有正常退出 0 且前后内容、HEAD、index 一致，才可显示“当前版本检查通过”；检查自己改了文件也须标为过时。新模型运行、内容变化或快照变化会使旧记录过时；读取检查摘要时重新核对当前内容，不依赖实时文件监听。

检查与模型共享串行资源门禁和工作区租约，不能同时改同一工作区。超时或中止必须处理应用自有进程；无法确认退出时阻止继续使用该工作区，不能声称所有后代进程已结束。输出按字节限制、截断标记，超时按配置限制；不存整套环境变量或认证头。

未运行检查依然明确 not_run。失败、过时和未运行不能合并成通过。保留现有人工接受语义，不在本批引入必需检查策略，也不自动接受、提交、合并或验收。

## C. 公共查询与联调交付

新增项目列表、准备工作区、检查启动/读取接口；现有任务查询增加 projectId/status 过滤，分页稳定。任务详情提供工作区准备状态、检查摘要和准确的 availableActions。新 DTO 使用明确状态，不让前端通过标题、时间或模型回复猜测事实。

所有新增接口沿用认证、Origin/Host、幂等键、版本冲突与结构化错误规则。公共客户端同步；现有单任务客户端调用不破坏。为 Claude 提供不含凭据的请求/响应样例及状态映射说明。待处理分组由实际状态确定，不额外调用 AI 整理。

## 验收与不做的事

- 两项任务使用不同 worktree/会话；替身各改一个文件，源码仓库保持不变。任务切换、反馈、事件补读、接受互不串数据；运行保持串行。
- 工作区准备重复请求、分支冲突、失败和重启中断有测试；不删除用户文件。旧数据库的任务与反馈回归通过。
- 检查通过、失败、超时、截断、改文件导致过时、新运行使旧检查过时有测试；不消耗模型额度。
- 全套测试、类型检查和必要的真实 Git/SQLite/HTTP 集成测试通过。Linux 无运行环境时明确未实测，不把 Windows 通过写成跨平台验收。
- 更新 BACKEND-USAGE.md、API-CLIENT-USAGE.md、结果报告及最新交接，列出未实现能力。

不做：前端迁移/美化、其他引擎、AI 自动拆分分派、执行队列、自动恢复未知进程、合并/集成/发布、自动清理 worktree、全局 Codex 配置修改。没有新增依赖的授权；优先内置模块和现有工具。
