# 第 2 批建议：单任务本机执行与审查后端

状态：v0.1 设计原文，2026-10-08（Asia/Shanghai）。用户已确认按 A 实施，当前交付见 [CODEX-BATCH-02-RESULTS.md](CODEX-BATCH-02-RESULTS.md)。以下保留设计阶段的范围选择与验收依据，不将建议自动扩展到 B/C。

## 目标与停止条件

在保留第一批验证器的前提下，让一个本机客户端能够保存任务、启动一次真实 Codex 运行、断线后读取事件、审查实际变更、反馈修改并明确接受某个变更版本。接口不依赖 Claude 的页面布局。

这是产品完整闭环的第一段：**执行 → 审查 → 修改 → 接受**。不把接受称为集成或最终验收；导入任意项目、自动 worktree、检查执行和代码集成另批推进。长期仍至少支持 Codex、Claude Code、DeepSeek Harness，本批只有 Codex 可执行。

## 本轮仓库核对

- `main` 尚无提交；`git status --short` 显示初始化文档、配置、`src/`、`tests/` 全部未跟踪。保留现状，不自动提交或清理。
- `src/codex/rpc.ts` 已有 JSONL、请求关联、服务端请求回调、事件回调、超时和直属子进程关闭机制。
- `src/codex/session.ts` 是探针：包含样例专用系统指令、固定策略、文本收集和轮次等待；没有可供业务订阅的公共事件接口。不能原样当产品适配器。
- `src/codex/approval.ts` 只允许关联正确的 `sample.txt` 普通更新；不能推广为任意仓库的审批策略。
- `src/workspace.ts` 创建独立样例 Git 仓库，提供固定样例断言与失败审计；没有 worktree 调度器。
- `src/verify.ts` 编排真实探针，临时 HTTP provider 配置也在其中。`tests/` 有协议、会话、审批、诊断和样例工作区测试。没有 HTTP、数据库、前端工程或项目依赖。

第一批结果文档中的 25 项测试、strict 检查和 Windows 真实调用均为历史证据。本轮只进行了文档和源码核对，没有重新运行测试、登录检查或模型调用。当前安装版本与账户可执行性不能由历史记录推断。

## 三种范围选择

| 方案 | 能证明什么 | 代价与限制 |
| --- | --- | --- |
| **A：专用仓库上的单任务 API（推荐）** | 任务、运行、事件持久化和真实执行审查闭环 | 不管理任意用户项目，不自动创建 worktree，不集成代码 |
| B：A 加单个 worktree 创建 | 从已有提交的项目隔离任务分支 | 增加脏仓库、分支冲突、路径与失败残留处理；需另一个可验收切片 |
| C：直接完成项目导入至最终交付 | 产品完整闭环 | 同时引入 worktree、检查执行、提交和集成，超出下一小批范围 |

推荐 A 的原因：先稳定前后端共同依赖的状态与事件边界，复用真实适配证据，避免把探针代码直接包成接口。A 验收后再讨论 B；不因方案选择预先搭建调度器。

## A 的明确范围

1. 单用户、本机 Node.js / TypeScript 服务，默认仅监听 `127.0.0.1`；没有前端页面也能通过 API 验收。
2. 启动前通过忽略的本地配置绑定一个专用测试 Git 仓库，要求有 HEAD、初始干净且不等于 AgentDesk 主仓库。可绑定人为准备的独立 worktree，但服务不创建、删除或修复 worktree。绑定目录只能服务一个任务；本批不提供释放后复用。
3. 保存任务目标、验收条件、执行实例、运行、归一化事件与审查快照。保留历史，服务重启后可查询。
4. 全服务只允许一个非终结运行；忙时返回冲突，不做排队、并发或自动重试。同任务反馈修改可产生下一次运行；使用同一工作区，并在已知会话内续接上下文。
5. Codex 使用结构化 App Server 协议；执行配置由后端提供受控配置项。工作目录、执行程序、权限策略不由单次浏览器请求自由覆盖。
6. 启动、文本事件、终态、实际 diff、反馈修改、请求中止、接受版本是本批核心动作。中止等待终态确认；关闭客户端连接不影响执行。
7. 浏览器刷新通过事件游标补读，不重复调用模型。服务进程重启后不自动重发任务；运行结果未知时标为待恢复并禁止继续执行，保留工作区供核查。本批不提供进程恢复或待恢复解除接口。

本批不是通用审批工作台：不开放接受文件审批、命令升级、提问回答或 steer 的业务 API。默认拒绝审批，未知请求返回不支持；需要人工动作时记录明确原因，不能伪造“等待用户”后挂住。沙箱内普通写入与需要升级的文件审批是不同路径。历史中已验证的审批/steer/resume 不因此变成产品已接入能力。

## 模块与复用方式

```text
本机客户端 → HTTP 接口 → TaskService / RunService
                              ├─ Store：对象、事件、幂等记录、审查快照
                              ├─ CodexAdapter → CodexSession / RpcClient
                              └─ RepositoryReader → Git 状态与 diff
```

- 通用类型只表达任务、运行和事件；原生 thread/turn/request 标识由 CodexAdapter 持有。执行引擎、配置实例、模型、会话分别记录。
- 候选目录为 `src/domain/`、`src/backend/`、`src/engines/`；这是职责划分，不要求每个概念创建一层类。根级配置和接口由 Codex 单一写入者维护。
- 对会话层做必要的小改动：显式传入执行配置与指令、提供订阅回调，保留探针的样例默认行为与历史测试。不能把 `samplePatchAllowed` 改成宽泛产品授权。
- `RpcClient` 的关闭与异常需要传递给运行管理器；业务层区分请求超时、真实失败和结果未知，不将所有异常转换成失败终态。
- 仓库读取复用参数数组调用 Git 的做法，新建通用读取函数；不让 `checkSample` 承担任意仓库审查。
- 不直接导入执行型 `verify.ts` 作为后端入口，不修改其验证目标或自动触发真实调用。HTTP provider 仍是显式配置，不在失败时偷偷切换模型/传输。

## 持久化与内容边界

推荐 SQLite 保存当前对象和有序事件，数据库置于忽略的 `.agentdesk/`。优先评估现有 Node 运行时的内置 SQLite；实施前核对实际版本、类型与 API，再确定实现。不新增第三方依赖，驱动不可用时报告并调整方案。

状态变化和对应事件在同一事务提交；启动记录与幂等键先持久化，再发原生请求。事务不能覆盖外部模型调用：崩溃窗口一律进入待恢复，避免自动重放产生两次执行。单服务实例独占数据库与工作区，第二实例拒绝启动。

产品任务正文和模型答复是本机业务数据，区别于第一批仅保存脱敏摘要。建议允许保存用户任务与归一化的可见答复，以便刷新后阅读；实现前需将这一内容边界列入启动说明。它们可能包含敏感内容，不能声称自动脱敏可靠。原始协议帧、stderr、认证配置、完整工具输出不入库。工具事件仅保留允许字段；本批没有完整日志查看器。

审查快照包含真实 tracked/staged/untracked 变化，不能只执行默认 `git diff`。接受绑定 HEAD、索引与工作树内容摘要；另存待审查差异以供本机查看。二进制、符号链接、不可读取或超限内容明确标示且本批禁止接受，不能悄悄省略后声称无变更。终止运行后重新计算快照，接受时再核对；有外部修改则拒绝旧快照。哈希核对不是文件系统沙箱或对恶意外部并发写入的保证。

## 状态与接口

字段、动作和错误草案见 [BACKEND-API-DRAFT.md](BACKEND-API-DRAFT.md)。主要约束：

- 任务状态、运行状态与阻塞原因分离；completed 只产生待审查。
- 反馈创建新运行，旧接受记录保留但失效。接受不会提交代码或触发集成。
- 检查结果本批固定为 `not_run`；验收条件只是用户输入，模型声称“测试通过”不能变成检查证据。
- 未接入引擎与未实现动作显式不可用；当前可用操作由本批能力、实例环境和运行状态共同计算。

## 实施后的验收标准

以下是未来验收要求，不是本轮通过记录。

| 场景 | 必须取得的证据 |
| --- | --- |
| 保存与重启 | 创建任务，重启服务，目标、条件、历史仍可查询；未触发模型执行 |
| 启动幂等与互斥 | 同一幂等键重复请求只产生一个运行；不同任务或第二次启动遇忙返回 409；冲突载荷不能复用键 |
| 真实单任务 | API 启动专用样例仓库的最小修改，获得真实终态、答复和预期 diff；主仓库不被执行器修改 |
| 刷新与补读 | 断开客户端后运行继续；从最后游标补读，事件无逻辑丢失、客户端可按 ID 去重 |
| 反馈与接受 | 对已完成运行反馈，产生第二运行；旧快照不可接受，接受当前快照后任务为 accepted；无提交/集成 |
| 真实中止 | 中止返回请求已记录，只有 interrupted 确认才能标 aborted；文件改动保留。未触发或未确认明确报告 |
| 故障与未知结果 | 模拟退出、启动超时、数据库写入失败及服务崩溃；不得伪造成功或自动重发；待恢复阻止新执行 |
| 差异完整性 | staged、untracked、删除、二进制、符号链接、超限、外部改动均有确定性测试；旧接受失效 |
| 本机接口边界 | 外部 Host/Origin、无本机访问凭证的写请求、任意 cwd/命令参数和未知引擎被拒绝；SSE 也受访问控制 |
| 工程与平台 | 新增确定性 API/状态/持久化测试，运行全套 `npm test` 与 strict typecheck；未配置 linter 如实标注。Windows 和 Linux 分别记录，缺少 Linux 环境则明确未验证 |

真实调用只针对专用样例、使用实际发现且可执行的模型，不因列表或握手成功判定可用。将新批次命令、退出码、时间、版本和最小证据写入独立结果文档；限额或网络阻塞时可交工程测试结果，但不能宣称真实闭环验收通过。

## 暂不做与下一批交接

不做前端重写、任意项目导入、worktree 创建/清理、并发调度、自动拆解、跨引擎交接、其他引擎执行、通用审批/提问、运行中补充、自动恢复、检查命令执行、Git 提交/合并、最终验收、推送和部署。完整工具输出与大文件审查也不在本批。

Claude 可依据接口草案检查字段与状态是否足够，但视觉方案继续独立评审；草案接口未上线，原型仍标模拟。本轮不向其他聊天派发消息。

评审重点是 A 是否足够作为下一小批，以及绑定专用仓库和暂不做审批/集成的取舍。范围确认后再拆具体实施步骤；未确认前不安装依赖、不创建服务或数据库、不改产品代码。后续再逐批补工作区创建、真实检查和集成验收，才能称为完整单任务交付。
