# AgentDesk 已确认产品与工作流

日期：2026-10-09。依据本轮用户逐项选择和确认。本文件是当前产品设计基线；目标能力不代表现有代码已经实现。旧设计、路线中不一致的分工、默认入口、多引擎范围和自动化边界以本文件为准。

## 定位与使用者

面向开发者的多 Agent 协作管理中心，解决同一项目中不同分工、多个会话之间频繁切换、上下文交接和遗漏事项的问题。开发者保留指挥权，软件负责组织、执行已批准操作和保存证据。

提供经过简单配置即可使用的成品软件。日常使用不要求手动启动前后端、输入 localhost 地址或复制内部访问令牌。支持 Windows / Linux；具体安装包、桌面宿主及后台常驻方案仍需工程设计。

软件管理流程图、角色、任务、会话、提醒、交接和集成；代码编辑、深入调试使用外部 IDE / 终端，提供对应 worktree 的打开入口。可以使用仓库、分支、commit、diff、worktree、冲突等开发术语；自动操作应展示真实命令、位置、配置与结果。

## 项目入口与接入

打开软件先进入全局项目管理首页，创建、查看、管理、选择 AgentDesk 项目，选择后进入该项目工作区。项目是本软件内部的组织空间；创建项目不等于创建 Agent 原生项目、代码仓库或立即执行任务。

支持从零开始和接入开发中的项目。接入已有项目的流程：

1. 选择已有 Git 仓库，检查分支、commit、未提交改动和已有 worktree；不自动重置、切分支、提交或覆盖改动。
2. 用户提供目标、已完成部分、问题与文档；负责人可分析仓库生成现状草案，由用户修正确认。代码存在不等于功能已验证完成。
3. 确定后续任务的 commit 基线。新 worktree 不自动包含原目录未提交改动；这些改动如何保存和纳入基线必须显式处理，具体交互待设计。
4. 无需补录完整历史，以已有成果为背景，建立剩余工作流程。区分用户确认的已有成果、分析待确认结果与本软件实际执行/审查证据。
5. 用户批准后续分工，再为开发任务建立会话与独立 worktree。

导入代码与导入其他工具的原生会话是不同能力；不假定能接管任意外部窗口或自动恢复其会话。

## 角色、任务与执行

- 角色配置可复用，保存职责、默认 Agent 工具和配置。
- 工作区绑定具体开发任务，不永久绑定某个 Agent。任务默认建立独立执行会话和 worktree。
- 同一种工具可同时建立多个任务会话；上下文不天然共享，项目约定和交接需显式提供。
- 同一任务的反馈优先继续原会话；更换执行者时明确交接，保留任务与代码依据。
- 首版目标支持 Codex、Claude、DeepSeek Harness，逐个适配、逐个验收；目前只有 Codex 有真实接入基础。

## 负责人及授权

从项目成员中指定负责人 Agent，不要求额外内置独立助手模型。用户可直接指挥各个 Agent，也可由负责人提出规划、分工、进展整理和交接建议。

分工与流程支持手动建立或负责人生成草案。用户可以修改、整批批准或只批准部分；未经批准的工作不启动。执行中新增节点、变更分工或依赖时，展示草案和受影响环节，确认后生效，不默默改写执行计划。

首版每个工作节点执行结束后等待用户确认，确认后才算完成；依赖满足不等于任意自动执行，后续工作仍须在已批准范围内。自动确认检查规则属于后续增强。

交接可以由用户直接发送，也可由负责人整理成果、相关文件、版本约定和未解决问题，经用户修改确认后发送。不同 Agent 不被视为自动知晓彼此完整对话。

## 项目流程图与会话

项目内以流程图/树形图展示工作拆分、分工、状态和依赖，能够看出哪些工作并行、哪些阻塞及其原因。节点采用两行：

```text
前端 · 登录页面
Claude Code · 实际模型名       执行中
```

工具和模型分别表达；模型以实际配置/运行返回值为准，历史保存每轮实际值。阻塞和待确认显示具体原因，不编造进度百分比。

点击节点在同一工作视图查看目标、进展、产出和会话，辅助信息按需展开。返回保留流程图位置。默认单会话，支持临时并排第二个会话；切换保留阅读位置与输入草稿。

## 提醒与生命周期

需要处理的事项关联具体任务和原因。软件内以角落弹窗提醒，不抢焦点、不自动切换会话；节点、任务和会话入口同步保留标记。关闭弹窗不等于解决事项。

切到 IDE / 终端或最小化时使用系统通知，点击定位对应任务。检测能力和用户权限应与实际运行环境相符。

有执行中的任务时，关闭软件询问后台继续或停止执行并退出；停止操作需确认真实退出，不回滚已有改动。后台继续、托盘、操作系统退出等具体生命周期待工程设计。

## 并行与集成

开发任务在独立 worktree 并行执行。代码目录隔离不等于运行资源或安全隔离，需配置依赖、端口、数据库、配置文件等环境。当前后端仍串行，不能把目标并行描述成已实现。

软件在用户确认后将具体成果集成到专用分支并执行检查；Git 冲突与功能不兼容需明确呈现，由开发者或指定 Agent 处理。执行结束、用户认可、代码集成、联合检查与最终验收分别表达，不自动推送、部署或擅自清理工作区。
