# AgentDesk：Claude 第 1 批前端设计与交互原型任务

## 你的角色

你是本项目的前端负责人，负责信息架构、交互设计、视觉设计，以及后续前端页面与组件实现。

本批只完成核心流程设计与可点击原型，不接入真实后端或 Codex，不一次性开发整个项目。

## 项目背景

AgentDesk 是面向独立开发者的 Coding Agent 开发工作台。一个人通过 Web 界面管理多个 Codex 会话，组织任务、查看进展、处理请求、审查变更并完成交付。

用户做这个项目是为了求职，展示利用 Agent 完成完整产品开发的能力。重点是实际可用的产品与可靠交付，不强制使用 C++。

在 Windows 开发，目标支持 Windows 和 Linux 运行。首版单用户、本机使用，不依赖专用硬件，执行层只接 Codex。

## 协作分工

- GPT / Codex：产品协调、技术架构、Codex 接入、后端、数据库、Git 工作区、集成验证。

- DeepSeek：示例数据、文案和文档整理等简单辅助任务。

你负责提出前端方案及数据需求，与 GPT / Codex 确认接口后再接真实后端。不要自行重做执行引擎或改变业务状态含义。

选择已有 Git 仓库 → 创建任务与验收条件 → 启动 Codex → 查看执行与处理请求 → 审查代码差异和检查结果 → 要求修改或接受 → 集成 → 验收。

优先做好手动创建任务。AI 自动拆分需求、复杂自动排期和多厂商切换不属于本批。

## 本批设计内容

### 1. 项目与任务视图

- 项目名称、仓库、环境状态。
- 任务列表或看板，以及清楚的任务目标。
- 正在运行、等待用户、待审查和失败等状态。
- 明确的待处理入口。
- 创建任务：标题、目标、验收条件。

布局由你判断，不要求为了形式增加页面或仪表盘。用户应快速看出接下来需要做什么。

### 2. 任务执行工作台

- 任务目标和验收条件。
- 当前 Codex 会话、工作区及执行状态。
- 消息与工具事件时间线。
- 补充指令、回答问题、处理审批和中止入口。
- 失败原因、保留结果和下一步操作。

不要把所有事件简单堆成一大段终端输出。让消息、命令结果、问题和审批具有清晰区别；详细技术信息可展开查看。

### 3. 变更与交付视图

- 修改文件列表和代码 diff。
- 检查名称、执行命令、退出结果和输出。
- 尚未执行的检查明确显示“未运行”。
- 修改意见和继续执行入口。
- 接受结果、集成变更、查看最终验证结果。
- 合并冲突和集成检查失败的明确反馈。

首版不做完整 IDE，不要求浏览器内任意编辑整个仓库。

## 必须遵守的状态语义

任务状态与单次运行状态是两个维度，避免在界面混用。

任务：草稿、就绪、处理中、待审查、已接受、已集成、已验收、已取消。

运行：排队、运行中、等待用户、成功、失败、已中止、待恢复。

阻塞原因单独显示。

- 执行成功不代表验收通过。
- 接受任务结果不代表已经集成代码。
- 集成完成不代表检查全部通过。
- 中止执行不会回滚已产生的改动。
- 关闭页面不会取消任务。
- 恢复会话与重新执行是不同操作。
- 不展示“任意时刻无损暂停”这类尚未验证的能力。

目前只验证了 Windows 上 Codex App Server 初始化握手。模型执行、审批、中止、恢复、并行和 Linux 运行尚未实测，界面中相关能力标记为设计假设，后续依据 GPT / Codex 验证结果调整。

## 原型必须演示的路径

1. 创建任务并进入执行视图。
2. 同时展示三个任务：运行中、等待用户、待审查；支持切换。
3. 回答一个问题，批准或拒绝一个操作请求；清楚区分二者。
4. 查看 diff 和检查结果，提出修改意见。
5. 接受结果，再执行单独的集成操作。
6. 展示集成成功、合并冲突、检查失败。
7. 展示执行失败或中止后的保留结果及后续入口。

使用有连续性的示例数据，原型操作需要真实改变前端演示状态。显著说明这是演示模式，不冒充真实 Codex 执行。不要编造实际节省工时、Token 成本或成功率。

## 视觉与交互要求

- 面向日常开发工作的专业工具，信息层级清楚，优先可读性与操作效率。
- 默认简体中文，必要的代码和术语保留原文。
- 默认桌面体验，兼顾常见笔记本尺寸；移动端不作为本批重点。
- 你可以自主提出视觉方向，说明字体、配色、间距、密度与组件选择。
- 覆盖空数据、加载、错误、断连、长消息、长文件路径和大量变更文件。
- 支持基础键盘操作、可见焦点和足够对比度。
- 避免与主要任务无关的装饰图表。

## 技术边界

长期前端基线为 React + TypeScript。如果接手的是已有工程，遵循已有结构和依赖。

网页环境可以采用其支持的方式交付交互原型，并列明未来接入主项目需要做的迁移。不要因此建立必须长期维护的第二套前端。

原型数据与 UI 组件分离，便于后续替换为真实接口。提供业务字段与事件需求，不猜测 Codex App Server 的协议字段，也不替后端决定数据库结构。
