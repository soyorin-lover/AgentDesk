## 先修的交互问题

以下位置相对于 Claude 的 `agentdesk-web` 工程。结论来自源码，复现步骤供后续浏览器复核。

1. **P1：接受状态跨任务共用。** `src/v2/AppV2.tsx:29` 使用应用级 `accepted` 布尔值，`:181` 传给任意任务头部，`:197` 控制任意审查页的已接受状态。接受 t144 后切换到其他任务，会继续用同一个 true 覆盖任务状态。应按任务与具体快照绑定接受记录，变更产生后失效；任务列表、概览、执行与审查使用同一来源。初版也需要守住这一状态语义。

2. **P2：接受弹窗缺少 Esc 与焦点约束。** `AppV2.tsx:70` 只处理辅助浮层的 Escape；`:245` 起的接受弹窗只提供遮罩和按钮关闭，没有弹窗 Escape 处理、Tab 焦点循环和关闭后焦点恢复。辅助浮层同时开启时，Esc 还可能先关闭后方辅助面板。应优先处理最上层弹窗并阻止键盘操作落到背景。

3. **P2：小窗口画廊预设不能证明自动降级。** `Gallery.tsx:81` 的 1024 帧明确带 `files=0&diff=unified`，由 `layout.tsx` 读取为预设。实际 `AppV2.tsx:147` 始终传入用户保存的 `layout.diff`，没有按可用宽度派生统一视图；文件栏也只在宽度不足时变浮层，并不会普遍自动收起。若保留交付描述中的自动行为，应实现不覆盖偏好的渲染降级，并从宽窗口直接缩小验证；否则将描述改为用户主动切换后的布局样例。

4. **P2：并排 diff 会截断代码。** `Panels.tsx:331`、`:336` 为代码单元格设置 `overflow: hidden` 与省略号，且表格固定布局。审查者无法从并排视图完整阅读长行。建议保留水平滚动或提供明确的完整行展开入口；统一视图可作补充，但不能无提示地省略审查内容。

这些是局部修正，不需要重做整套视觉设计。任务创建、交付页面、空状态与失联画面属于已声明的本轮缺口，不作为本轮越界漏做要求。

## 接口与检查版本

v1 的 `docs/03-前端接口需求.md` 仍可作为需求清单，不能当作已实现契约。v2 当前从 `data.ts` 读取演示常量，没有真实后端调用。真实接口以本项目 [BACKEND-USAGE.md](BACKEND-USAGE.md) 和 `src/backend/types.ts` 为准。

“检查结果过时”不能只增加提交号：模型修改通常尚未提交，同一个 HEAD 下工作区内容可以多次变化。应绑定任务、运行、快照 ID 与内容摘要（`Snapshot.id`、`runId`、`contentDigest`），提交号只作为附加上下文。

当前后端已有快照和接受时的内容重验，变化时返回 `snapshot_stale`；这不等于已经实现检查执行或持续监听磁盘变化。当前 `checks` 恒为 `not_run`。前端 `AppV2.tsx:189` 的固定“2 项通过”及 `data.ts` 的示例检查输出必须保留为演示，真实模式不得沿用。

最小联调切片：单专用仓库、`codex-local`、单任务顺序运行，覆盖创建/启动、事件补读、终态、真实 diff 快照、反馈修改、接受与冲突提示。运行中补充指令、审批、恢复、换实例、检查执行、集成和最终验收均按当前能力隐藏或禁用，不从第一批协议验证推断为第二批业务 API 已支持。

开发联调还需处理准确来源 `http://localhost:5273` 的允许配置、Bearer 请求头、携带 Authorization 的 fetch SSE、事件 seq 去重补读，以及 `Idempotency-Key` / `expectedVersion`。令牌不写进前端源码或 URL；服务地址/令牌配置采用独立本地连接入口。UI 从服务返回的能力和 `availableActions` 决定可执行操作。
