# AgentDesk 前端原型

面向独立开发者的多 Coding Agent 开发工作台。**第 2 轮：视觉与交互重设计（v2）**。

> ⚠️ **演示数据**：全部为构造内容，不来自真实执行。不会调用 Codex，不产生真实代码改动，也不代表真实的工时、Token 或成功率节省。

---

## 快速开始

在 Windows PowerShell（含旧版）中分两行执行，避免 `&&`：

```powershell
cd "E:\Coding project\Claude\agentdesk-web"
```

```powershell
npm run dev
```

| 地址 | 内容 |
|---|---|
| `http://localhost:5273` | **v2**（当前迭代：交互修正 + 接口对齐） |
| `http://localhost:5273/?gallery=1` | 评审画廊：固定尺寸的关键画面，可交互 |
| `http://localhost:5273/v1.html` | v1 旧版原型（深色，保留比较） |

端口若被占用，`vite.config.ts` 已设 `strictPort: false`，会顺延到下一个可用端口；以终端输出的地址为准。

其他命令：

```powershell
npm run typecheck
```

```powershell
npm run build
```

`build` 同时产出两个入口，v2 与 v1 互不导入。

## 从 v1 到 v2 改了什么

| 方面 | v1 | v2 |
|---|---|---|
| 主题 | 深色 | 浅色（本轮要求） |
| 结构 | 三栏常驻 | 侧栏 + 单主区 + 按需辅助面板 |
| 状态 | 双彩色徽章并列 | 一句准确的话 + 圆点（默认灰） |
| 跨任务待处理 | 常驻右栏 | 侧栏计数 + 概览分组 + 待处理页 |
| 工具活动 | 每条命令一张卡片 | 折叠成一行；失败与进行中项不隐藏 |
| 代码审查 | 中栏内嵌 | 独立视图，代码占满宽度，并排可选 |
| 空间 | 固定栅格 | 可开合 + 可拖动 + 宽度自适应 |
| 引擎 | Codex 专用措辞 | 引擎 / 实例 / 模型分离，未接入项隔离 |
| 正文宽度 | 跟随容器 | 固定 760px，面板开合不改变行长 |

**保留自 v1 的部分**：状态语义不变式（执行完成 ≠ 接受 ≠ 集成 ≠ 验收）、未运行检查必须写明、中止不回滚、恢复 ≠ 重跑、补充指令不新建运行、检查证据必须显示真实命令与退出码。这些逻辑在 v2 中原样成立，只是换了表达方式。

## 接口边界（重要）

本轮已把前端**对齐到真实后端契约**，但**尚未接线**。

- 契约层：`src/v2/backend/types.ts` 逐字段对齐主项目 `src/backend/types.ts`。
- 演示数据经 `src/v2/backend/demo.ts` 转换后才能进入界面；组件不直接读原始素材。
- **检查恒为「未运行」**：后端 `checks` 的类型是单字面量 `'not_run'`，真实模式结构上无法表达「检查通过」。
- **接受绑定三字段**：`runId` / `snapshotId` / `contentDigest`。提交号只作附加上下文，不参与相等判断。
- **未支持的能力不显示为可执行**：审批、运行中补充指令、恢复、换实例、集成、检查执行在本批后端没有 API，界面保留位置并写明原因。
- 最小联调方案（8 步切片、连接入口、待确认项）见 [docs/v2-04](docs/v2-04-接口对齐与联调方案.md)。

## 布局规则

一条从窗口宽度往下推的分配规则，不是一堆媒体查询：

```
窗口宽度
 ├─ 先满足主区最小宽度（执行 560 / 审查 640 / 页面 520）
 ├─ 再给辅助面板（320–640px）
 ├─ 再给文件列表（200–420px，仅审查）
 └─ 最后给侧栏（展开 236px / 收起 56px）
```

放不下就降级最后一项：侧栏先收为图标轨；仍不够，辅助面板转浮层（Esc 关闭）。

**降级不写回用户偏好** —— 窗口变大后自动恢复。实测从 1500 缩到 900，`localStorage` 中的偏好一次都没有被覆盖。

diff 的显示方式同理：宽度不足时**渲染**降级为统一视图，保存的 `split` 偏好不变。

## 迁移到主项目

v2 仍是 Vite + React + TS，没有引入非标准技术，也不会迫使主项目维护第二套工程。

**运行时依赖只有 `react` / `react-dom`。** 无图标库、无 UI 库、无状态管理库、无 CSS 框架 —— 图标是内联 SVG，状态用 `useState`，样式是 CSS 变量加手写规则。

### 步骤

1. **搬运** `src/v2/` 中的 `domain 无关部分`：`bits.tsx`、`icons.tsx`、`layout.tsx`（去掉样稿分支）、`v2.css`、`AppV2.tsx`、`Sidebar.tsx`、`pages.tsx`、`RunView.tsx`、`Panels.tsx`。这些不依赖 Vite 特性。
2. **删除** `src/v2/Gallery.tsx`、`src/v2/data.ts`，以及 `layout.tsx` 中 `SHOT` 相关的 URL 覆盖分支和 `main.tsx` 里的画廊分发。
3. **接真实数据**：按 [docs/03-前端接口需求.md](docs/03-前端接口需求.md) 的字段形状新增 `src/api/` 适配层，替换 `data.ts` 的直接导入。
4. **删除 v1**：`src/components/`、`src/domain/`、`src/mock/`、`src/state/`、`src/styles/`、`v1.html` 与 `main-v1.tsx`。
5. **补齐本批未做的**：事件流订阅（替换演示数据）、长会话虚拟滚动、检查结果「过时」标记（需后端提供检查对应的提交标识）。
