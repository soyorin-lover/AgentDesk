# v2 视觉规范

数值的唯一来源是 `src/v2/v2.css` 的 `:root`。本文档解释取值理由。

---

## 1. 三层表面

```
外框  #F4F5F7   ← 导航、页面之间、留白
工作面 #FFFFFF  ← 当前工作区域（带 1px 描边 + 极轻阴影）
低层填充 #F6F7F9 / #EEF0F3  ← 代码块、选中、分组
```

**为什么是三层而不是更多**：参考图都只有这一组关系。v1 用了七八级明度阶梯，结果层级反而读不出来。v2 里"哪一层"由**用途**决定，不由深浅决定。

工作面用 `box-shadow: 0 0 0 1px var(--line)` 描边而不是 `border`——这样它和圆角、阴影可以一起计算，不会因为 border 改变内部宽度导致子元素对不齐。

---

## 2. 文字四级与正文尺寸

| 角色 | 值 | 用途 | 对比度（白底） |
|---|---|---|---|
| 主文字 | `#1F2329` | 标题、正文 | 15.6:1 |
| 次要 | `#5A6170` | 说明、列表副标题 | 7.4:1 |
| 三级 | `#868D9A` | 元信息、时间 | 3.5:1（不承载语义） |
| 代码 | `#2B313C` | diff、命令 | 13.4:1 |

**正文字号 15px 起，行高 1.75。** 提示词明确要求"舒适的文字尺寸和行距"、"不要为了显得专业而缩小文字"。v1 用 13px 基准，在浅色背景下显得单薄。15/1.75 是中文长段落舒适阅读的常见组合（对比：DESIGN.md 建议 16px 起，1.5 行高）。

字号阶梯：

```
--fs-meta  12    元信息、标签
--fs-ui    13.5  界面文字、列表
--fs-body  15    正文、消息
--fs-h3    16    区块标题
--fs-h2    19    页面标题
--fs-h1    24    最高级标题（概览页项目名）
--fs-code  12.5  代码
```

**阅读宽度固定 760px**（`--read`）。这直接来自参考图的分屏态：并排查看材料时，正文不该被拉宽。

---

## 3. 颜色：只在需要时出现

提示词要求"避免大面积警报色、密集状态徽章"。v2 的策略是**状态默认是灰的**。

| 语义 | 色值 | 出现条件 |
|---|---|---|
| 交互强调 | `#3A62D2` | 主按钮、链接、焦点、执行中 |
| 成功 | `#1D7F55` | 检查通过、已集成、已验证 |
| 警告 | `#9A5C00` / 点 `#D48A1C` | 等待确认、未运行的检查 |
| 失败 | `#C03A2F` | 执行失败、检查失败 |
| 待审查 | `#6450C4` | 待审查状态（与强调色区分） |

**最关键的改动：状态不再是彩色胶囊。** 状态是一个 7px 圆点 + 一行文字：

```
● 执行中      蓝点
● 等待你确认  橙点 + 橙字
● 待审查      紫点
● 执行失败    红点 + 红字
● 执行完成    绿点（唯一允许用绿色标记的普通状态）
○ 草稿        虚线空心圈
```

正常运行时页面上几乎看不到彩色。这是与 v1 最大的观感差异——v1 每个任务行都有两枚彩色徽章，8 个任务就是 16 处色块。

---

## 4. 排版与对齐

- 正文最大宽度 760px，`margin: 0 auto` 居中。辅助面板开合时**不改变**宽度，只是两侧留白变化。
- 对话流里：用户消息右对齐、浅灰底、不对称圆角（`14px 14px 4px 14px`）；智能体消息左对齐无底，纯正文。
- 列表用**细线分隔**（`1px #E7E9ED`）而不是卡片包裹。行高 52px，悬停时整行浅灰。
- 页面左右留白 32px（小屏 24px），顶部 36px。

**最小间距单位 4px**：4 / 8 / 10 / 12 / 16 / 22 / 32 / 36。

---

## 5. 圆角与阴影

| 元素 | 圆角 |
|---|---|
| 按钮、输入、行内卡片 | 7px |
| 卡片、实例行 | 10px |
| 工作面、对话框 | 12–14px |
| 胶囊（筛选、提示） | 99px |
| 引擎标识方块 | 6px |

阴影只用于**浮层**：
- 工作面：`0 0 0 1px 描边 + 0 1px 2px + 0 2px 10px`（几乎不可见，只是把白面和背景分开）
- 输入框：同上
- 浮层面板 / 对话框：`0 10px 32px rgba(20,24,33,.12)`

卡片、列表、嵌入块**一律无阴影**。这是"避免过多阴影"这条要求的实现。

## 6. 组件状态

| 组件 | 默认 | 悬停 | 选中/激活 | 焦点 |
|---|---|---|---|---|
| 导航项 | 透明 | 浅灰底 | 白底 + 1px 描边 + 加粗 | 2px 蓝环 |
| 按钮（次） | 白底 + 描边 | 浅灰底 | 按下更深 | 蓝环 |
| 按钮（主） | 蓝底白字 | 深蓝 | — | 蓝环 |
| 分段切换 | 透明 | 文字变深 | 白底 + 轻阴影 | 蓝环 |
| 列表行 | 透明 | 浅灰底（整行） | 当前项浅灰 | 蓝环 |
| 文件项 | 透明 | 浅灰底 | 浅蓝底 + 蓝字 | 蓝环 |
| 输入框 | 1px 描边 | — | 聚焦时蓝描边 + 3px 浅蓝光晕 | 同上 |

**焦点环**：`0 0 0 2px #fff, 0 0 0 4px rgba(58,98,210,.55)`。两段式的第一段用白色内衬，保证在浅灰底和彩底上都可见。

**禁用**：文字转三级灰，背景转填充色，`cursor: not-allowed`。主按钮禁用时用 45% 透明度的蓝，而不是变灰——保持"这是主操作"的认知。

## 7. 图标

- 16×16 视框，线宽 1.4，圆角端点与连接，`stroke: currentColor`
- 全部为内联 SVG 路径（`src/v2/icons.tsx`），不引入图标库
- 界面里 14px 为主，密集处 13px，导航 16px
- 图标默认 `aria-hidden`，只在承载语义时给 `aria-label`
- **引擎标识是中性字母方块**（`Cx` / `CC` / `DS`），不使用三套品牌色——避免三家配色混杂，也避免让未接入的引擎看起来已经可用

## 8. 代码与 diff

| | 统一视图 | 并排视图 |
|---|---|---|
| 行号 | 左右两列 | 各自一列 |
| 新增行 | 文字底 `#ECF8F0`，行号底 `#DCF1E3`，标记 `+` 绿 | 同左（右半） |
| 删除行 | 文字底 `#FDF0EF`，行号底 `#F8DFDC`，标记 `−` 红 | 同左（左半） |
| 区块头 | `#F5F7FB` 底，显示 `@@ -14 +14 @@` 与所属函数签名 | 跨列 |
| 空白对齐 | — | 空缺侧用 `#FAFBFC` 留白，不压缩行高 |

- 代码字号 12.5px，行高 1.7
- 长行在代码区域内横向滚动，**页面本身不产生横向滚动**
- 并排视图用 `table-layout: fixed` + `text-overflow: ellipsis`，超长行截断而不是撑破布局
- 宽度不足时默认切统一视图（1024px 以下由用户或自动规则决定）

**真实数据验证过布局**：`src/integrations/billing-provider/adapters/legacy-v2/normalizeTransactionPayload.ts`（73 字符深路径）与 `src/api/__tests__/__snapshots__/errors.test.ts.snap`（长文件名）在文件列表里都正确省略而不溢出。

## 9. 动效

| 动效 | 时长 | 用途 |
|---|---|---|
| 悬停 / 选中背景 | 160ms `cubic-bezier(.2,0,0,1)` | 反馈 |
| 浮层面板滑入 | 180ms | 出现 |
| 遮罩淡入 | 140ms | 出现 |
| 加载转圈 | 900ms 循环 | 执行中 |

`prefers-reduced-motion: reduce` 时关闭所有过渡，转圈降速到 3s（不是停住——仍需表达"正在进行"）。

DESIGN.md 建议 120–220ms，与实现一致。

---

## 10. 无障碍与缩放

- 主文字 15.6:1、次要 7.4:1，均超 WCAG AA
- 三级灰（3.5:1）只用于元信息，不承载语义。**不靠过浅文字营造安静感**——安静感来自留白与低对比边框，不是来自低对比文字
- 状态同时有圆点、文字、（必要时）颜色三重编码
- 所有交互元素可 Tab 到达并有可见焦点环
- 分隔线可聚焦，方向键调整宽度，双击恢复默认
- 浏览器缩放到 150% 时不遮挡操作：所有尺寸用 px 但布局基于 flex + 最小宽度约束，无固定高度容器包裹文字
- 输入法组合态（`isComposing`）不会触发发送
