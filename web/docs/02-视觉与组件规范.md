# 视觉与组件规范

设计令牌的单一来源是 `src/styles/tokens.css`，本文档解释取值理由。改样式应改令牌，不在组件里写魔法值。

---

## 1. 视觉方向

**定位**：日常开发工具，不是展示页。用户一天要在这里待几小时。

**倾向**：
- 深色为默认。开发者的终端与编辑器多半是深色，切来切去不该有明暗跳变。
- 信息密度高，但用留白和分组控制，不靠缩小字号压信息。
- 层级靠**明度与边框**，不靠阴影堆叠。阴影只用于模态框（需要脱离文档流）。
- 动效克制：只用于表达"正在发生"（脉冲、渐隐），不做装饰性过渡。

**明确避免**：渐变色块、大圆角卡片、装饰性图标、与决策无关的图表。

---

## 2. 色板

### 中性色（九级明度阶梯）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bg-canvas` | `#0e1116` | 应用底色 |
| `--bg-panel` | `#141821` | 主要面板（左栏、右栏、卡片） |
| `--bg-raised` | `#1a1f2a` | 悬浮层、需要抬升的卡片 |
| `--bg-inset` | `#0a0d12` | 内凹区域（代码块、输入框） |
| `--bg-hover` | `#1f2531` | 悬停态 |
| `--bg-active` | `#252c3a` | 按下态 |
| `--bg-selected` | `#1c2740` | 选中态（带蓝调，与悬停区分） |
| `--border-subtle` | `#1e2430` | 最弱分隔 |
| `--border` | `#262d3a` | 常规边框 |
| `--border-strong` | `#333b4b` | 交互元素边框 |

### 文本四级

| 令牌 | 值 | 用途 | 对比度（对 `--bg-panel`） |
|---|---|---|---|
| `--text` | `#e4e8f0` | 正文 | 13.2:1 |
| `--text-secondary` | `#99a2b4` | 次要说明 | 6.4:1 |
| `--text-muted` | `#6c7488` | 标签、元信息 | 3.6:1（仅用于非关键信息） |
| `--text-faint` | `#4d5464` | 装饰性（行号、分隔） | 2.2:1（不承载语义） |

### 语义状态色

每个状态有**三件套**：`前景 / 背景 / 边框`。只用前景色会在大面积背景上难以辨认，只用背景色在灰度下会丢失。

| 语义 | 前景 | 背景 | 边框 | 用于 |
|---|---|---|---|---|
| 运行中 / 处理中 | `#4a9eff` | `#12273f` | `#1f4f80` | 运行中、审批请求 |
| 等待用户 / 阻塞 | `#e8a33d` | `#33260f` | `#6b4c17` | 等待回答、警告、演示标记 |
| 待审查 | `#a682f5` | `#251c3d` | `#4b3a7d` | 待审查状态 |
| 成功 / 通过 | `#3ecf8e` | `#102c22` | `#1f6045` | 通过、已接受、已集成 |
| 失败 / 冲突 | `#f0564a` | `#341816` | `#7a2a24` | 失败、冲突、未满足 |
| 中止 / 中性 | `#8b93a5` | `#20252f` | `#3a4150` | 未运行、已取消、草稿 |

**选择理由**：六色在色相上分散（210° / 33° / 265° / 155° / 5° / 220°），对红绿色盲用户，失败色（红）与成功色（绿）的**明度**相差明显（`#f0564a` 亮度 0.30 vs `#3ecf8e` 亮度 0.66），不依赖色相区分。

### 强调色

`--accent: #5b8cff`。用于主按钮、选中态、焦点环。与"运行中"蓝 `#4a9eff` 刻意不同——避免用户把品牌色误读成状态色。

## 3. 排版

### 字体

```
--font-ui:  Inter, -apple-system, BlinkMacSystemFont, 'Segoe UI',
            'Microsoft YaHei', 'PingFang SC', system-ui, sans-serif
--font-mono: 'JetBrains Mono', 'Cascadia Mono', Consolas, 'SF Mono', Menlo, monospace
```

中文回退到 `Microsoft YaHei`（Windows）/ `PingFang SC`（macOS）。等宽字体优先 `JetBrains Mono`，回退到 Windows 自带的 `Cascadia Mono`——Git Bash 与 VS Code 用户已装，无需打包字体文件。

### 字号阶梯（八级）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--fs-2xs` | 10px | 分组标题、大写标签 |
| `--fs-xs` | 11px | 元信息、时间戳、行号 |
| `--fs-sm` | 12px | 次要正文、按钮、命令 |
| `--fs-base` | 13px | **正文基准** |
| `--fs-md` | 14px | 强调正文、提问标题 |
| `--fs-lg` | 16px | 模态框标题 |
| `--fs-xl` | 19px | 任务标题 |

正文基准取 13px 而非 16px：这是高密度工具界面（参考 VS Code 的 13px、Linear 的默认字号）。16px 会让一屏能看到的命令输出行数明显减少。

### 行高

- 界面文字 `1.6`（中文需要更松的行高才好读）
- 标题 `1.3`
- 代码 `1.55`

---

## 4. 间距与圆角

**4px 基准**：`--sp-1`=2, `--sp-2`=4, `--sp-3`=6, `--sp-4`=8, `--sp-5`=12, `--sp-6`=16, `--sp-7`=20, `--sp-8`=24, `--sp-9`=32。

4 的倍数便于在 1x / 1.5x / 2x 缩放下都落在整数像素上，避免边框模糊。

**圆角**：`--r-sm`=3（芯片、行内）、`--r-md`=5（按钮、输入框、小卡片）、`--r-lg`=8（大卡片、模态框）、`--r-full`=999（胶囊芯片）。

圆角普遍偏小（5px 而非 8-12px）。工具类界面里大圆角会让密集列表显得松散。

## 5. 布局尺寸

| 令牌 | 值 | 理由 |
|---|---|---|
| `--w-rail` | 296px | 容得下 3 个芯片 + 两行标题 |
| `--w-pending` | 344px | 比左栏宽，因为待处理卡片内容更多 |
| `--h-topbar` | 48px | 容得下 30px 按钮 + 上下各 9px |

中栏最小可用宽度约 560px（`1600 - 296 - 344 - 边距`）。本批按桌面优化，不专门适配窄屏——提示词明确移动端不是本批重点。

### 时间线的事件视觉区分

这是"不要把事件堆成一大段终端输出"这条要求的实现：

| 事件 | 左侧图标 | 容器形式 |
|---|---|---|
| 用户消息 | 人形 | 蓝色描边方块，左对齐 |
| Codex 消息 | 星形 | 无容器，纯文本 |
| 思考摘要 | 芯片 | 折叠块 |
| 命令 | 终端 | 卡片：命令行 + 折叠输出 |
| 文件变更 | diff | 卡片：摘要 + 可展开 diff |
| 计划 | 层叠 | 卡片 |
| 提问 | 问号 | 黄色左边框卡片 + 选项列表 |
| 审批 | 盾牌 | 蓝色左边框卡片 + 命令原文 + 四个决策按钮 |
| 错误 | × | 红色横幅 + 折叠详情 |
| 警告 | 三角 | 黄色横幅 |
| 中止 | 停止 | 横幅 + "改动已保留"说明 |
| 状态信息 | i | 单行浅色文字 |

提问与审批用**黄色 / 蓝色左边框**区分，且按钮数量不同（提问 1 个提交按钮，审批 4 个决策按钮）——两者含义完全不同，视觉上不能相似。

## 7. 焦点与对比度

**焦点环**：
```css
--focus-ring: 0 0 0 2px var(--bg-canvas), 0 0 0 4px var(--accent);
```
两段式：第一段用背景色做内衬，让焦点环与元素之间有空隙，第二段是可见的蓝色环。单段环在深色背景上容易与按钮边框混淆。

**对比度检查**：

| 组合 | 比值 | 标准 |
|---|---|---|
| `--text` on `--bg-panel` | 13.2:1 | AAA |
| `--text-secondary` on `--bg-panel` | 6.4:1 | AA |
| 状态色前景 on 各自状态背景 | ≥ 5.2:1 | AA |
| `--text-on-accent` on `--accent` | 4.9:1 | AA |

`--text-muted`（3.6:1）与 `--text-faint`（2.2:1）**只用于不承载语义的信息**（分组标题、行号、装饰分隔）。承载信息的文字不用这两个等级。

**不依赖单一通道**：
- 状态 = 颜色 + 文字 + （任务/运行）形状差异
- 演示模式 = 颜色 + "演示"文字
- 未运行 = 斜纹底 + "未运行"文字 + 灰色时钟图标

## 8. 动效

| 动效 | 用途 | 时长 |
|---|---|---|
| `.pulse`（透明度 + 缩放） | 表达"正在进行" | 1.6s 循环 |
| `.loadbar`（扫光） | 加载进度 | 1.1s 循环 |
| `.toast-in` | 提示出现 | 140ms |
| 折叠三角旋转 | 展开状态 | 90ms |
| 悬停背景 | 反馈 | 90ms |

全部在 `@media (prefers-reduced-motion: reduce)` 下关闭脉冲动效。

没有页面切换过渡、没有元素入场动画。工具界面的动效只应用来表达状态，不用来炫技。
