## 4. 空间分配实测

| 窗口 | 视图 | 侧栏 | 辅助面板 | 结果 |
|---|---|---|---|---|
| 1440×900 | 执行（面板关） | 展开 236px | — | 主区 1196px，正文 760px 居中 |
| 1440×900 | 执行 + 文件面板 400px | 展开 | 并排 400px | 主区 740px，正文宽度不变 |

## 6. 业务含义准确性（对照 PRODUCT.md v0.2 与提示词 §五）

| 规则 | 实现 | 实测 |
|---|---|---|
| 执行完成 / 接受 / 集成 / 验收 是不同阶段 | 状态文案分别为「执行完成」「已接受 · 未集成」「已集成 · 待验收」「已验收」 | ✅ 四者措辞不同，未合并为「完成」 |
| 关闭页面不取消运行 | 执行视图运行状态行写明「离开页面不影响执行」 | ✅ |
| 中止不回滚已有变更 | 中止按钮 `title` 写明「已写入的文件不会回滚」；失败卡片列出保留改动的文件数与行数 | ✅ |
| 会话恢复 ≠ 恢复已结束的系统进程 | 恢复按钮 `title` 写明「不会恢复已结束的系统进程」 | ✅ |
| 各引擎能力分别验证 | 智能体页能力矩阵标注「属于 Codex 引擎」，逐项显示已验证/部分验证/未验证，并注明依据 CODEX-BATCH-01-RESULTS.md | ✅ 未把 Codex 能力复制给其他引擎 |
| 原型与模拟执行明确标示 | 侧栏底部常驻「演示数据 · 未连接后端」；接受/拒绝后结果行附「演示：未发送到真实引擎」 | ✅ 常驻但不占工作空间 |
| 检查未运行必须写明 | 决策条一句话点出是哪两项 + 原因（缺 `BILLING_API_TOKEN` / 本轮没执行）；检查面板逐项写「未运行」 | ✅ 未画成通过 |
| 任务状态与运行状态不混用 | 合并为一句准确的话（如「等待你确认」），不再并排两枚徽章 | ✅ 消除了 v1 的双状态标签 |
| 多引擎：换模型 ≠ 换引擎 | 引擎 / 实例 / 模型三层分别表达 | ✅ 同一 Codex 下两个实例用不同模型 |
