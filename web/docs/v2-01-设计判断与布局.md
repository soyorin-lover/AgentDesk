# v2 设计判断与布局方案

日期：2026-10-08 · 状态：待评审 · 取代 v1 原型的视觉与信息结构

本轮重新判断视觉语言与信息结构。**保留** v1 中经得起推敲的状态语义与交互逻辑（执行/接受/集成/验收分离、未运行检查必须写明、中止不回滚、恢复≠重跑），**重做**视觉语言、导航结构、空间组织。

---

## 1. 从参考图提炼的共同语言

用户提供 4 张参考：Codex 桌面端、Codex 分屏态、Claude 桌面端、DeepSeek Harness。提炼出的四点是**设计思维**，不是外观参数：

**1. 一个中性外框，一个纯白工作面。**
Codex 与 Claude 都是「浅灰外框 + 白色主区」的两层结构。外框负责导航与全局状态，工作面完全让给内容。这解决了 v1 最大的问题——深色三栏等宽并列，没有任何一处是"主体"。

**2. 输入区是一个明确的悬浮对象，不是一条工具栏。**
四张参考的输入框都是圆角容器，底部一行放"模式/模型/发送"，与上方的对话内容有清晰的边界。DeepSeek 那张尤其明显：输入框带独立阴影浮在内容之上。这提示输入区应该是一个**有形状的组件**，而不是我 v1 里那种贴在页底的横条。

**3. 辅助栏默认收起，按需展开，且展开后可调整。**
Codex 第二张图把工具/推荐放在右侧独立面板，与主区并排；Claude 那张是「对话 + 编辑器分屏」。共同点是：辅助区域**可以不存在**，需要时出现，且不改变主区的信息密度。

**4. 工具活动就地折叠成一句话，不铺成日志。**
Claude 那张的"已编辑 4 个文件 +313 −3"与"再显示 1 个文件"是典型做法：用一行摘要代替一屏事件，把真实内容放在展开之后。

**没有照搬的地方**：不复制 Codex 的左侧图标轨＋侧栏双层结构（对本产品的任务量过重）；不复制 Claude 的分屏编辑器（本产品不做 IDE）；不做 DeepSeek 那种顶部多标签页。

## 2. 信息层级：为什么从三栏改为「导航 + 单主区 + 按需面板」

v1 是三栏常驻（任务列表 / 任务详情 / 待处理队列）。三个问题：

1. **没有主体。** 三栏都在争注意力，用户第一眼不知道该看哪里。
2. **状态重复。** 同一个"等待确认"在左栏列表、任务头部、右栏队列各出现一次。
3. **空间死板。** 中栏永远被两侧挤压，代码审查时看不了几行 diff——而审查恰恰是最需要宽度的场景。

v2 的结构：

```
┌──────────┬──────────────────────────────────────────────┐
│          │ 上下文栏：位置 · 标题 · 状态 · 智能体 · 视图   │
│  侧栏    ├──────────────────────────────────────────────┤
│  导航    │                                              │
│  + 进行中 ├────────────── 主区（唯一主体）────────┬──────┤
│  的任务   │                                      │ 辅助 │
│          │   概览 / 任务列表 / 待处理 / 智能体    │ 面板 │
│          │   执行会话 / 代码审查                 │(按需)│
│          │                                      │      │
│          ├──────────────────────────────────────┴──────┤
│          │ 决策条（仅审查视图：检查摘要 + 要求修改/接受） │
└──────────┴──────────────────────────────────────────────┘
```

**每个界面只有一个主体**：
- 概览页 → 主体是"接下来做什么"
- 执行视图 → 主体是当前这次工作
- 审查视图 → 主体是代码
- 智能体页 → 主体是实例与可用性

**状态只在一个地方说明。** 侧栏用最小的圆点 + 计数负责"提醒"，任务页用一行文字 + 上下文完整说明。不再是三处重复同一条状态。

**跨任务待处理不做常驻右栏**（提示词明确不要求），改为：
- 侧栏「待处理」项带数字
- 概览页首屏「需要你处理」分组
- 专门的待处理页按类型分组

代价是待处理事项不是"一直可见"的。权衡：常驻右栏会让审查视图永久损失约 340px 宽度，而这个损失每天都发生；而待处理事项一天只看几次。**用侧栏计数 + 概览首屏 + 悬停摘要（`title` 给出任务名与状态）补偿。**

## 3. 模块关系

| 模块 | 目的 | 为什么是这个形态 |
|---|---|---|
| 概览 | 建立当前方向、快速进入下一步 | 内容少，用单栏流式排布。不做统计卡片——没有可靠数据就不展示百分比 |
| 任务列表 | 整理与选择任务 | 表格化行（标题/智能体/状态/时间）。看板留作后续，本批不做 |
| 待处理 | 集中作决定 | 按「等待确认 / 执行失败 / 等待审查」分组。只列需要动作的事项，不当日志流 |
| 执行 | 理解进展、下指令、处理决策 | 固定阅读宽度的会话流 + 底部输入区，与参考图一致 |
| 审查 | 充分阅读代码后决定 | 代码占满宽度；检查证据放决策条 + 可开合面板 |
| 智能体 | 了解"能不能用" | 按引擎分组，以**实例**为单位；能力矩阵直接引用真实运行证据 |
| 交付 | 集成与验收 | 本轮未实现；入口保留 |

「执行」与「审查」是同一任务的两种视图，通过上下文栏的分段切换，不占导航。**切换时机是自动的**：任务进入待审查状态后分段才出现（`inReview` / `failed` / `accepted`），普通执行中的任务没有审查入口——因为那时还没有可审查的稳定版本。

## 4. 布局规则（可开合与自适应）

这是本轮提示词的硬要求。实现为**一条从窗口宽度往下推的分配规则**，而不是一堆媒体查询。

### 优先级

```
窗口宽度
  ├─ 先满足主区最小宽度（执行 560 / 审查 640 / 页面 520）
  ├─ 再给辅助面板（320–640px）
  ├─ 再给文件列表（200–420px，仅审查）
  └─ 最后给侧栏（展开 236px / 收起 56px）
```

任何一步放不下，就降级**最后一项**：侧栏先收为图标轨；仍不够，辅助面板改为浮层盖在主区上（Esc 关闭）。

### 关键性质

**1. 降级不覆盖用户偏好。**
侧栏收起是"这次渲染时收"，不是写回设置。窗口变大后自动恢复展开。实现上是 `autoRail = navRail && !wantRail`——实际渲染收起了，但保存的偏好仍是展开。

**2. 主区永远不会被压到不可用。**
主区最小宽度是硬约束。辅助面板宁可转浮层，也不让 diff 挤成一条缝。

**3. 阅读宽度不随面板开合变化。**
执行视图的正文固定 `760px` 居中（`--read`）。打开面板时，主区变窄，两侧留白变少，**行长不变**。这是参考图（Claude 分屏态）最值得学的点：并排查看材料不应该把正文拉成 200 字一行的宽条。

**4. 面板一次只开一个。**
辅助面板是同一个容器，内部切换「详情 / 文件 / 变更 / 检查」。避免多个侧栏叠加。

**5. 开合不丢东西。**
- 输入草稿：`localStorage`，按任务分别保存
- 面板宽度、侧栏状态、diff 模式、文件列表宽度：`localStorage` 全局保存
- 选中文件、滚动位置：组件内状态，切换面板不重置

### 已验证的空间行为

| 场景 | 结果 |
|---|---|
| 1440×900 执行 + 面板 400px | 侧栏展开，主区 740px，面板 400px 并排 |
| 1440×900 执行 + 面板 560px | 侧栏**自动**收为 56px 图标轨，正文宽度不变 |
| 1280×800 执行 + 面板 360px | 侧栏自动收起，主区与面板并排保留 |
| 1024×720 审查 + 检查面板 | 侧栏图标轨；面板改**浮层**盖在 diff 上（Esc 关闭）；文件列表收起为 diff 顶部入口；diff 自动切统一视图 |

均已在浏览器中实测（见验收记录）。

## 5. 决策必要信息不随"渐进展开"隐藏

提示词明确：失败与审批影响属于决策必要信息，不能折叠。实现规则：

| 信息 | 处理 |
|---|---|
| 待确认请求 | **不可折叠**。就地展开动作、理由、影响范围、文件列表与增删行数 |
| 失败 | **不可折叠**。即使所在的工作过程分组被收起，失败的那条命令仍然显示（`act__pinned`） |
| 进行中的步骤 | 同上，始终可见 |
| 未运行的检查 | 决策条上一句话写明是哪两项 + 原因；完整列表在检查面板 |
| 已保留的改动 | 失败卡片里直接写出文件数与行数，并给"查看"入口 |
| 命令原始输出、完整检查输出、运行历史、技术标识 | 可折叠——这些是证据，不是决策前提 |

## 6. 键盘与连续使用

| 快捷键 | 作用 |
|---|---|
| `Ctrl+\` | 侧栏展开 / 收起 |
| `Ctrl+.` | 辅助面板开合 |
| `Esc` | 关闭浮层面板 / 关闭对话框 |
| `J` / `K` | 审查视图：下一个 / 上一个文件 |
| `Enter` / `Shift+Enter` | 发送 / 换行（正确处理中文输入法组合态 `isComposing`） |
| `Tab` | 所有交互元素可达；分隔线可聚焦，`←/→` 调整宽度（`Shift` 加速） |

拖动分隔线支持鼠标与指针事件；双击恢复默认宽度。分隔线有 `role="separator"` 与 `aria-valuenow/min/max`。

**浏览器位置**：使用 hash 路由（`#/task/t142/review`），因此前进/后退与直接打开链接都可用。

**长时间执行**：执行中页面顶部说明"离开页面不影响执行"，中止按钮就在旁边。不强迫用户停留。

## 7. 与 v1 的差异

| 方面 | v1 | v2 |
|---|---|---|
| 主题 | 深色 | 浅色（本轮要求） |
| 结构 | 三栏常驻 | 侧栏 + 单主区 + 按需面板 |
| 状态表达 | 双芯片并列（任务状态 + 运行状态） | 一句准确的话 + 圆点 |
| 跨任务待处理 | 常驻右栏 | 侧栏计数 + 概览分组 + 待处理页 |
| 任务切换 | 左栏完整任务列表常驻 | 侧栏只列进行中的任务；完整列表在任务页 |
| 工具活动 | 每条命令一张卡片 | 折叠成一句话；失败与进行中项不隐藏 |
| 代码审查 | 中栏内嵌 diff | 独立视图，代码占满宽度，并排可选 |
| 空间 | 固定栅格 | 可开合 + 可拖动 + 宽度自适应 |
| 引擎 | Codex 专用措辞 | 引擎 / 实例 / 模型分离；未接入引擎明确隔离 |
| 正文宽度 | 跟随容器 | 固定 760px |

v1 保留在 `v1.html`，便于逐项对比。
